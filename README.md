# Zelda Maker Toolkit для PS Maker

Плагин для [PS Maker (Pixel Stories)](https://pixelstories.io/), который добавляет боевую систему в реальном времени и инструменты 2D action-adventure игр в духе классических top-down приключений (ориентир — *A Link to the Past*): меч с заряженным круговым ударом, щит, бомбы, бумеранг, лук, магию, врагов с ИИ, интерактивный мир, головоломки, подземелья, HUD и сохранения.

Всё настраивается через **штатный редактор событий PS Maker**: плагин регистрирует 42 действия `Zelda: …`, которые автор ставит в On-load события карты, триггеры и диалоги.

> Статус: **0.4.2, MVP** (сверено с PS Maker 1.2). Логика покрыта 170 юнит-тестами и 19 интеграционными проверками в настоящем Phaser 3.90 (headless Chromium) через эмулятор хоста PS Maker. В PS Maker подтверждено пользователем: плагин загружается, формы действий открываются, в playtest запускаются HUD и панель диагностики. Бой и враги в самом PS Maker ещё не подтверждены. Что нужно проверить вручную — см. [docs/TESTING.md](docs/TESTING.md).

## Установка

1. Скопируйте `dist/zelda-maker-toolkit.ps-maker.js` в папку `/plugins` вашего проекта PS Maker (плагины — бета-функция PS Maker; файл загружается автоматически).
2. В редакторе событий карты добавьте первым On-load событием **`Zelda: Start Toolkit`** и задайте `Map ID` (уникальное имя карты — по нему запоминаются сундуки, двери и переключатели).
3. Добавьте врагов и объекты действиями `Zelda: Create Enemy`, `Zelda: Create Object`, `Zelda: Create Chest`, `Zelda: Create Door`.

Сборка из исходников:

```bash
npm install
npm run build          # официальный @ps-maker/plugin-cli → dist/zelda-maker-toolkit.ps-maker.js
npm run check          # typecheck + юнит-тесты + сборка + интеграционный тест в Chromium
npm run harness        # демо в браузере: http://127.0.0.1:8080/examples/harness/
```

Нужен Node.js ≥ 22.18 (тесты запускаются встроенным `node --test` с удалением типов TypeScript).

## Быстрый старт (On-load события карты)

| # | Действие | Параметры |
|---|---|---|
| 1 | `Zelda: Start Toolkit` | Map ID = `field`, Preset = `alttp` |
| 2 | `Zelda: Create Enemy` | Template = `slime`, Position = точка на карте |
| 3 | `Zelda: Create Chest` | ID = `chest_1`, Item = `boomerang` |
| 4 | `Zelda: Create Object` | Type = `button`, ID = `gate_switch` |
| 5 | `Zelda: Create Door` | ID = `gate`, Lock = `switch` |
| 6 | `Zelda: Add Rule` | When = `{"switchOn":"gate_switch"}`, Then = `[{"openDoor":"gate"}]` |

Для действий плагинов PS Maker показывает параметр *Position* как два числовых поля X/Y (кнопки **Set position**, как у встроенных событий, у плагинов нет — проверено в редакторе, PS Maker с плагином 0.2.0). Чтобы не подбирать числа вручную, включите в игре оверлей **F9** и **кликните по карте**: точка отметится, появится «X: … Y: …», а `x, y` скопируется в буфер обмена. Где точка нужна в правиле или маршруте патруля, поставьте `Zelda: Place Marker` один раз и дальше ссылайтесь на неё по имени (`"at": "boss_spot"`, *Patrol markers* = `p1,p2`).

Управление по умолчанию (меняется через `Zelda: Configure`): стрелки/WASD — движение PS Maker; **X** — меч (удерживать — круговой удар); **C** — предмет; **Q/E** — смена предмета; **Z** — поднять/бросить/открыть (та же клавиша, что взаимодействие в PS Maker); **V** — щит в режиме `hold`; **I** — панель предметов; **F9** — хитбоксы (клик по карте — координаты); **F10** — диагностика.

## Возможности

- **Бой**: фазы удара (подготовка/удар/восстановление), хитбокс только в активной фазе, не более N попаданий по цели за удар, отбрасывание, заряд и круговой удар, «тычок» при заряде, неуязвимость с миганием, смерть и возрождение.
- **Предметы**: бомбы (фитиль, радиус, цепная реакция, разрушение), бумеранг (оглушение, возврат, переключатели, сбор предметов), лук и стрелы, щит (фронтальная блокировка по типам урона), огненный жезл и лечебное заклинание (магия), крюк (экспериментально). Новые предметы — JSON-ом (`Zelda: Define Item`) или через JS API.
- **Враги**: 6 шаблонов на 5 поведениях — ближний бой, стрелок, защищающийся рыцарь, патрульный, многофазный мини-босс; сопротивления по типам урона, выпадение предметов, «усыновление» NPC из редактора.
- **Мир**: кусты, трава, горшки и камни (поднять и бросить), разрушаемые блоки и стены, рычаги, кнопки, нажимные плиты, толкаемые блоки, сундуки, двери с ключами, скрытые проходы, факелы, шипы, ямы, столбы для крюка, таблички.
- **Головоломки и подземелья**: правила «условие → действия» (22 условия, 31 действие, расширяемо), последовательности переключателей, комнаты с волнами врагов, ключи и большой ключ на подземелье, боссы, завершение подземелья.
- **HUD в классическом стиле**: шкала магии, рамка предмета, пиксельные счётчики, «— LIFE —» и сердца по 10 в ряд, сообщения в рамках, панель предметов; раскладка проверена тестами на отсутствие наложений на 10 разрешениях; отдельная Phaser-сцена; русский и английский.
- **Спрайт-листы**: атаки игрока (тело + слой оружия) и анимации врагов из ваших листов, например Mana Seed; просмотрщик кадров с номерами — [docs/SPRITES.md](docs/SPRITES.md).
- **Звук и NPC PS Maker**: звуки моментов боя из аудио-ассетов (`Zelda: Set Sound`); враги и снаряды не проходят сквозь NPC (коллизии NPC появились в PS Maker 1.1).
- **Диагностика**: F10 или `Zelda: Debug` — панель с позициями, глубинами, ближайшими объектами и последними предупреждениями прямо на экране.
- **Сохранения**: версионированный формат в `localStorage`, миграции, санитизация старых/повреждённых данных, автосохранение на ключевых событиях.
- **Отладка**: оверлей хитбоксов и состояний (F9), логирование с уровнями, DOM-события для внешних инструментов.

## Главные ограничения

API плагинов PS Maker (`@ps-maker/plugin-api@0.0.3`) даёт только пользовательские действия и контекст `{ game, scene, player }`. Поэтому:

- ветвления событий PS Maker по состоянию Toolkit невозможны — используйте правила Toolkit (`Zelda: Add Rule`, `Zelda: Run Actions`);
- встроенные переменные, инвентарь, диалоги и сохранения PS Maker плагину недоступны — Toolkit ведёт собственные;
- движением игрока управляет PS Maker; отбрасывание и блокировка на время удара делаются коррекцией позиции спрайта после шага физики;
- форматы параметров `position`, `npc`, `image` не задокументированы — плагин принимает все правдоподобные варианты и пишет в лог, если не распознал.

Подробно — в [docs/ENGINE_AUDIT.md](docs/ENGINE_AUDIT.md).
