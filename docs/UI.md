# Интерфейс: HUD, окна сообщений и диалогов, уведомления, главное меню, настройки, сохранения

С 0.17.0; сообщения диалогом PS Maker — с 0.18.0; с 0.27.0 — роль *HUD* в списке ролей, окно реплик NPC (`Zelda: Dialogue`) и уведомления из дизайнера; HUD в окне игры редактора и масштаб «как карта» — с 0.19.0; иконки предметов и панель инвентаря из своих картинок — с 0.20.0; с 0.22.0 сообщения показывает только диалог PS Maker, а сохраняет только PS Maker; с 0.23.0 HUD и экраны меню собираются мышью в дизайнере на карте редактора (`Zelda: UI Layout` вместо `Zelda: HUD Style`); с 0.24.0 — меню по правому щелчку, выделение нескольких, прилипание, группы, поворот, фигуры полос, иконки из листа, слоты быстрого доступа, мини-карта, слои и звуки экранов; с 0.26.0 у экранов есть роль — меню паузы (Escape), окно сообщений, инвентарь (I), титульный экран — и `Zelda: Message Style` удалён. Что рисует PS Maker, а что Toolkit:

| Что | Кто рисует | Где настраивается |
|---|---|---|
| Главное меню | Toolkit (экран с ролью *Title*) или PS Maker (**Add UI**) | титульная карта проекта |
| Настройки (громкость, полный экран, сохранить, выход) | PS Maker (меню опций) | Game UI → Options menu; открывается Escape, а при меню паузы Toolkit — его кнопкой |
| Загрузка сохранений | PS Maker (меню загрузки) | Game UI → Load game menu |
| Реплики NPC и выбор ответа | Toolkit: экран с ролью *Dialogue box* (без него — окно сообщений, без него — диалог PS Maker) | `Zelda: Dialogue`; `Zelda: UI Layout`, тексты `{speaker}`, `{message}`, картинка `{portrait}`, элемент *Choice list* |
| Сцены со штатными портретами PS Maker | PS Maker (**Dialogue**, **Choices**) | Game UI → Dialogue layouts, Choice layouts |
| HUD: сердца, счётчики, рамка предмета, шкала магии, свои картинки и надписи | Toolkit, в пикселях карты | `Zelda: UI Layout` — дизайнер на карте редактора |
| Экраны меню поверх игры (пауза, магазин, карта) с кнопками | Toolkit | `Zelda: UI Layout` с именем экрана; `Zelda: Open UI Screen`; роль *Pause menu* — Escape |
| Инвентарь (I) | Toolkit: экран с ролью *Inventory* или встроенная панель | `Zelda: UI Layout`, элемент *Inventory grid* |
| Свои надписи и шкалы из значений Toolkit (по желанию) | PS Maker (**Add UI**) по переменным | `Zelda: Show Stat In Variable` + Add UI |
| Таблички, «Получено…», подсказки | Toolkit: экран с ролью *Message box* (без него — короткие уведомления) | `Zelda: UI Layout`, текст `{message}` |
| Короткие уведомления («Получено: Бомбы ×5», «Сохранено») | Toolkit: экран с ролью *Notifications* (без него — встроенная плашка) | `Zelda: UI Layout`, текст `{note}` |
| Сохранение и загрузка | PS Maker (меню опций и загрузки) | `Start Toolkit` → **Progress variable** |

## Дизайнер HUD и экранов — `Zelda: UI Layout`

Идея — как у дизайнеров HUD для RPG Maker: интерфейс собирается мышью из элементов прямо в редакторе, без чисел в полях. Код и данные таких плагинов не использовались.

**Как начать.**
1. Поставьте `Zelda: UI Layout` в «Map start» после `Start Toolkit` на **одной** карте (обычно первой). Поле **Screen name** пустое — это HUD. С 0.25.0 он общий для всего проекта: каждая карта без своего HUD показывает его (Toolkit берёт его из данных проекта, которые PS Maker держит в каждой карте), и правка в одном месте видна везде. Рамка на других картах показывает этот HUD с подписью «the shared HUD from map …».
   - Свой HUD для отдельной карты: ещё один `UI Layout` на ней с галочкой **This map only**.
   - Общий HUD в проекте один — первый по порядку карт. Второй `UI Layout` без *This map only* на другой карте игра не показывает (в консоли — предупреждение), а дизайнер, открытый на нём, предупреждает жёлтой плашкой: удалите его или поставьте *This map only*. Так бывает в проектах, собранных до 0.25.0, где HUD копировался на каждую карту (в том числе в демо).
2. Откройте действие (щелчок по нему в списке или по HUD в жёлтой рамке *Game window* на карте). Слева появляется панель **Zelda UI designer**, а HUD в рамке становится редактируемым.
3. Без данных дизайнер начинает с классического HUD Zelda (с 0.35.0 это только шаблон: пока HUD не собран в дизайнере, его в игре нет). Кнопка **Classic HUD** возвращает этот шаблон (Undo отменяет).

**Работа с элементами** (как в графическом редакторе):
- Щелчок по элементу — выбрать (элемент группы выбирается со всей группой, с Alt — один); Shift+щелчок — добавить к выбору; рамка, растянутая по пустому месту, выбирает всё, что задела. В списке панели щелчок выбирает ровно этот элемент.
- Перетаскивание двигает выбранное. Края и центры прилипают к краям и центру окна игры и к краям других элементов (розовые направляющие); Alt — без прилипания. В разделе **Designer** панели — **Grid** (шаг сетки 2–16 пикселей) и **Snap to edges**.
- Белые квадраты вокруг выбранного — изменить размер (Shift — сохранить пропорции); золотая точка над картинкой, текстом или иконкой — повернуть (Shift — шагами по 15°). У сердец и счётчика размер задают их картинки.
- **Правый щелчок** по пустому месту — меню *Create here*: элемент создаётся там, где щёлкнули; *Paste here*, *Select all*. По элементу — *Copy / Cut / Paste / Duplicate*, порядок (*Bring to front*, *Forward*, *Backward*, *Send to back*), *Group / Ungroup*, *Lock / Unlock*, *Delete*; для нескольких — выравнивание по краям и центрам и *Space evenly*.
- Клавиши (когда курсор не в поле панели): стрелки — сдвиг на 1 пиксель (Shift — на 8), Delete, Ctrl+Z / Ctrl+Y, Ctrl+C / X / V / D, Ctrl+A, Ctrl+G (Ctrl+Shift+G — разгруппировать), Ctrl+] / Ctrl+[ (с Shift — на самый верх / низ), Escape.
- Заблокированный элемент (*Lock*) не ловит щелчки на карте — удобно для фона-панели; выбрать его можно в списке.
- Колесо мыши и средняя кнопка над рамкой по-прежнему прокручивают и масштабируют карту.
- Элемент можно вынести за рамку: слой дизайнера покрывает рамку вместе со всеми элементами и их ручками, так что щелчок по такому элементу тоже не уходит карте и объектам под ним.

Мышь над рамкой берёт слой страницы поверх карты, а не сама карта: редактор PS Maker не отдаёт щелчки по такому слою своим инструментам карты (тот же механизм, что у его собственных кнопок поверх карты), поэтому настройка интерфейса не рисует и не выделяет ничего на карте.

Каждое изменение дизайнер вписывает в поле **Layout data** действия так же, как ввод с клавиатуры, и PS Maker сохраняет его с картой. Поле руками не правьте; оно хранит до 50 000 символов (около 150 элементов) — дизайнер предупредит, если макет не помещается.

**Элементы** (все размеры — в пикселях макета; при **Scale** 0 пиксель макета равен пикселю карты):

| Элемент | Что показывает | Настройки |
|---|---|---|
| Picture | картинку из Images | растянуть, 9-slice (размер угла) или вписать; поворот; цвет, если картинки нет |
| Text | текст со значениями в фигурных скобках: `{rupees}`, `{health}`, `{var:<id переменной>}`, `{t:hud.life}`, `{language}` (название языка игры, с 0.33.0); на экранах — `{message}`, `{inv.name}`, `{inv.description}`, `{inv.count}` | шрифт проекта, размер, цвет, выравнивание, поворот, обводка (цвет и толщина; без неё — мягкая тень), перенос строк по ширине (**Wrap lines at the width**) |
| Bar | полосу значения: здоровье, магия, переменная… | значение и максимум; фигура — прямоугольник, «пилюля», круг, ромб, треугольник, звезда, сердце; направление заполнения; цвета заливки, фона и рамки, толщина рамки; подпись (`HP`, `{health}/{maxHealth}`); или картинки заливки и фона |
| Hearts | сердца по здоровью игрока | картинки полного, половины и пустого, сколько в ряд, зазор |
| Counter | значок над числом | значение, значок, лента цифр (десять цифр `0123456789` в ряд одной ширины), число разрядов |
| Item box | иконку предмета на кнопке предмета | какая кнопка (первая C или вторая B), картинка рамки |
| Icon | одну иконку из листа иконок | лист (картинка из Images), размер клетки, номер — кнопка *Pick the icon…* показывает лист, иконка выбирается щелчком; поворот |
| Quick slot | слот быстрого доступа: N-й предмет, который можно взять в руку (как по Q/E) | номер слота 1–9, рамка, рамка выбранного слота, показывать клавишу. Клавиши 1–9 берут предмет своего слота в руку (`controls.hotbar`), пока в HUD есть слоты |
| Minimap | упрощённую карту вокруг игрока: стены (коллизии карты), врагов, твёрдые объекты Toolkit | круг или прямоугольник, сколько пикселей карты до края, цвета фона, рамки, стен, игрока, врагов, объектов |
| Button | кнопку экрана (ниже) | картинка, картинка выбранной, цвета, текст, действие |
| Choice list | варианты ответа `Zelda: Dialogue` (окно диалога, ниже) | шрифт, размер, цвета, текст перед выбранным, высота строки, зазор, картинки строки и выбранной строки |
| Key bindings | клавиши и кнопки геймпада игрока — экран управления (ниже) | шрифт, размер, цвета, высота строки, где начинаются столбцы клавиатуры и геймпада (0 — столбец не показан) |
| Inventory grid | предметы игрока сеткой (экран инвентаря, ниже) | столбцов, размер клетки, зазор, картинка клетки, картинка курсора, показывать запас (бомбы, стрелы) |

Общие настройки: **Anchor** — от какого угла или края окна игры отсчитываются X и Y (элемент у правого края остаётся у него на любом размере окна; при смене якоря элемент остаётся на месте); **Opacity**; **Effect** — мигание, пульсация, покачивание, дрожание (пока элемент виден; в редакторе эффект не проигрывается); **Shown** — всегда, пока переменная проекта включена (не 0 и не пустая), пока у игрока есть предмет или пока значение сравнивается с числом (например, *Health* ≤ 2 — надпись «LOW HEALTH» в демо); **Hide during dialogue**.

Раздел **Layout**: **Scale** (0 — как карта), шрифт и цвет текста по умолчанию, картинки встроенной панели инвентаря (клавиша I без экрана *Inventory*) и курсора, **Item icons** — свои иконки встроенных предметов в рамке предмета и в инвентаре (у предметов `Define Item` — их поле *Icon*).

## Экраны меню

`Zelda: UI Layout` с именем в **Screen name** (например, `pause`) — экран поверх игры: панель, надписи, кнопки. В дизайнере он рисуется на затемнении, раздел **Screen** панели задаёт:
- **Role** — для чего экран (с 0.26.0), ниже;
- **Pause the game** — пока экран открыт, Toolkit стоит, а игрок не ходит (по умолчанию включено);
- **Dim colour** — цвет поверх игры (`#rrggbbaa`, пусто — без затемнения);
- **Sound: opens / closes / selection moves / button pressed** — звуки проекта;
- **Takes the keys (a menu)** (только у роли *Plain*) — снимите, и экран станет *слоем* над HUD (полоса здоровья босса, надпись, таймер): игра идёт под ним, клавиши остаются игре, открывается `Open UI Screen`, закрывается только `Close UI Screen` с его именем. Слоёв может быть открыто несколько, меню рисуется над ними.

**Роль** (с 0.26.0; *Dialogue box* и *Notifications* — с 0.27.0; *HUD* — обычная роль с 0.28.0) выбирается первым полем раздела и говорит, что это за макет. Все роли устроены одинаково: роль хранится в самом макете, смена роли ничего больше не меняет, а в проекте работает **первый макет каждой роли по порядку карт** — про остальные дизайнер пишет жёлтой плашкой «Not used in the game: … on map … is the one used». Исключения два: у *HUD* есть галочка **This map only** (свой HUD для одной карты), а *Plain* и *Title* открываются по имени (`Open UI Screen`), поэтому таких экранов может быть много — по одному на имя; без имени такой экран получает имя роли (`screen`, `title`, с номером, если занято).

**Screen name** — только имя, по которому экран открывают `Open UI Screen` и кнопки. Макет без имени и без роли — HUD (так делались HUD до 0.28.0, они так и остаются HUD).

В проекте у каждой роли работает первый такой экран по порядку карт:

| Роль | Что открывает | Что закрывает | Что ещё |
|---|---|---|---|
| *HUD* | всегда на экране | — | без имени экрана; общий для проекта или *This map only* |
| *Plain* | `Open UI Screen`, кнопка другого экрана | X, I, Escape; кнопка *Close* | — |
| *Pause menu* | Escape (клавиша Menu, `Set Controls`) во время игры | Escape, X, I; кнопка *Close* | меню опций PS Maker открывается кнопкой с событием «Open game options menu» (в демо — *Settings*) |
| *Settings* (с 0.34.0) | действие PS Maker «Open game options menu» (кнопки паузы и титула с этим событием), кнопка *Open a screen*, Escape — если нет меню паузы | Escape, X, I; кнопка *Close* | вместо меню опций PS Maker; шестерёнка PS Maker скрыта; см. «Экран настроек» |
| *Message box* | сообщения Toolkit выбранных видов | Z, X или Escape на последней странице | см. «Сообщения Toolkit» |
| *Dialogue box* | `Zelda: Dialogue` | Z, X или Escape на последней странице | см. «Реплики NPC» |
| *Notifications* | каждое короткое уведомление, на его время | само, когда время уведомления вышло | слой: игра идёт; см. «Уведомления» |
| *Inventory* | I (клавиша инвентаря) во время игры, вместо встроенной панели | I, X, Escape | элемент *Inventory grid*: стрелки двигают курсор, Z, C или щелчок ставят предмет на первую кнопку, B — на вторую |
| *Title* | `Open UI Screen` на титульной карте | ничего (кнопка с событием Change map уводит с карты) | HUD скрыт; Escape остаётся у PS Maker |

**Escape и меню опций PS Maker.** PS Maker открывает меню опций по Escape (управление проекта *Open options*). Когда в проекте есть экран с ролью *Pause menu*, Escape во время игры открывает его, а меню опций не открывается: Toolkit перехватывает нажатие раньше PS Maker и отмечает его обработанным, а меню опций PS Maker такие нажатия пропускает (ENGINE_AUDIT, раздел 24). Пока экран Toolkit открыт, Escape закрывает его. Пока открыто меню опций PS Maker (игра на паузе), Escape закрывает его, как обычно. Без экрана паузы Escape полностью остаётся PS Maker. Шестерёнка опций в углу экрана (Game UI → Options menu → кнопка) работает всегда.

Открыть экран можно и действием `Zelda: Open UI Screen` (по имени) из любого события, закрыть — `Zelda: Close UI Screen` (без имени — открытый экран, с именем — этот экран или слой, *All screens* — все). Экраны, открытые с другого экрана, возвращаются к нему. Экран, сделанный на любой карте, открывается на всех картах проекта (с 0.25.0; при одинаковых именах — первый по порядку карт). В редакторе рамка экрана показывает и то, что под ним: HUD этой карты под затемнением, кроме титульного экрана. Экраны, как и HUD, рисует Toolkit. Чтобы HUD не было видно (интерфейс на UI-компонентах PS Maker), удалите все его элементы в дизайнере: пустой HUD ничего не рисует, а экраны работают. Галочки *Show HUD*, *Magic bar* и *HUD at the bottom* у `Start Toolkit` убраны в 0.32.1 — всё это теперь в дизайнере.

**Кнопки.** Стрелки (и крестовина геймпада) переводят выбор на ближайшую кнопку в этом направлении, клавиша действия (Z) или щелчок мыши нажимает, наведение мыши выбирает. Меч (X), инвентарь (I) или Menu (Escape) — назад (кроме титульного экрана). Кнопка делает одно из: **Run a PS Maker event** — событие проекта или карты (через штатное действие PS Maker «Run event», поэтому в событии работает всё: Dialogue, Change map, меню опций, переменные); **Open a screen**; **Close this screen**; **Set a variable** — переменной проекта значение из поля *Value*; **Reset the player's controls** — забыть свои клавиши игрока (с 0.32.0); **Change the language** — язык игры из таблицы переводов: код в поле *Language*, пусто — следующий язык (с 0.33.0, [TRANSLATIONS.md](TRANSLATIONS.md)); с 0.34.0 — громкость, полный экран, сохранение, загрузка и выход (см. «Экран настроек»). Пока открыт диалог PS Maker из события кнопки, экран клавиши не берёт. Выбранная кнопка рисуется картинкой *Picture when selected*, а без неё — с золотой рамкой.

## Экран настроек (роль *Settings*, с 0.34.0)

Замена стандартного меню опций PS Maker экраном из дизайнера.

- **Как открывается.** Действие PS Maker *Open game options menu* (в событии кнопки паузы, титульного экрана или любого события) открывает этот экран вместо меню PS Maker: Toolkit подменяет действие, пока оно выполняется (ENGINE_AUDIT, раздел 28), проект не меняется. Ещё его можно открыть кнопкой *Open a screen* по имени, а Escape открывает его, если в проекте нет меню паузы.
- **Шестерёнка PS Maker** (кнопка опций поверх игры) скрывается, пока в проекте есть экран настроек: она открыла бы меню PS Maker. Без экрана настроек её убирают в PS Maker: *Game UI → Options menu → Options button in game*.
- **Кнопки** (*When pressed*):
  - **Music volume**, **Sound volume** — громкость музыки и звуков (те же настройки игрока, что в меню PS Maker; PS Maker хранит их в браузере, звуки Toolkit им подчиняются). Стрелки влево и вправо на выбранной кнопке меняют громкость на шаг (поле *Volume step*, пусто — 10), Z — на шаг вверх, после 100 — в 0;
  - **Fullscreen on / off** — полный экран (действие PS Maker *Toggle fullscreen*);
  - **Change the language** — язык игры (стрелки влево и вправо — предыдущий и следующий);
  - **Exit game** — выход (действие PS Maker *Exit game*);
  - и все прежние: *Open a screen* (управление), *Close*, *Run a PS Maker event*…
- **Тексты и полосы**: `{musicVolume}`, `{soundVolume}` (0–100; полоса с *Value* `musicVolume` и *Max* `100`), `{fullscreen}` (1 или 0), `{fullscreen.text}` («Вкл» / «Выкл»), `{language}`. *Max* полосы теперь может быть числом.
- `{settings.exit}` (и `{settings.save}`) — 1 или 0, по галочкам *Show exit game button* / *Show save game button* действия *Open game options menu*, которое открыло экран. Условие показа кнопки выхода: *compare* `settings.exit == 1`.
- **Сохранение и загрузка — в меню паузы** (с 0.35.0, как просил пользователь): кнопки **Save game** (действие PS Maker *Save game*, затем уведомление «Игра сохранена.») и **Load game (PS Maker's menu)** (меню загрузки PS Maker) работают на любом экране, в демо они стоят в паузе.

## HUD на карте в редакторе

На любой карте проекта, в котором есть `Zelda: Start Toolkit` (с 0.35.0; раньше — только на карте с ним), редактор показывает жёлтую пунктирную рамку **Game window** — экран игры в начале (размер окна игры из Game settings, делённый на масштаб карты, с центром в точке старта игрока из **Move player**). В рамке HUD нарисован так же, как в игре: тот же код рисования, те же картинки и пиксели. Щелчок по HUD открывает его `UI Layout`; когда открыто действие экрана, рамка показывает этот экран.

HUD рисуется поверх игры, поэтому в игре его место не зависит от камеры: рамка в редакторе показывает, что закроет HUD в первом кадре.

**Переход с `HUD Style` (до 0.23.0).** Действие `Zelda: HUD Style` удалено. Если оно осталось в старом проекте, PS Maker в игре пропускает его (в консоли — `No plugin action handler found for: plugin:zelda-maker-toolkit:zelda-hud-style`, так устроен `StoryRunner` 1.2.1) и выполняет следующие действия; HUD становится классическим. Удалите его, добавьте `Zelda: UI Layout` и выберите те же картинки в дизайнере (у сердец, счётчиков, рамки предмета, шкалы магии и у фона-картинки с 9-slice).

## Шрифты

**Загрузка.** PS Maker загружает шрифт проекта только тогда, когда впервые показывает свой текст: меню, диалог или текст Add UI. Если тест запущен прямо с игровой карты, этого может не случиться. С 0.18.0 Toolkit сам загружает выбранный шрифт из папки ассетов проекта под тем же именем, что использует PS Maker. Пока шрифт грузится, текст рисуется запасным шрифтом без засечек и перерисовывается после загрузки.

**Русский текст и шрифт.** PixelOperator — шрифт нового проекта PS Maker — **без кириллицы**. Русские буквы в нём браузер берёт из другого шрифта (обычно с засечками), и надписи выглядят «не тем шрифтом»: «Получено: Бумеранг!», «- ЖИЗНЬ -», таблички на русском. Тексты Toolkit по-русски, когда язык Toolkit — *auto* и браузер или система русские. Добавьте в Game UI → Fonts пиксельный шрифт с кириллицей и выберите его в макете диалога (Dialogue layouts → стиль текста), в стилях кнопок и в дизайнере `Zelda: UI Layout` → **Font**. В демо так сделано со шрифтом Pixelify Sans (SIL Open Font License 1.1).

## Сообщения Toolkit — экран с ролью *Message box*

Без такого экрана сообщения Toolkit — короткие заметки над игрой. С ним выбранные сообщения показываются в окне, собранном в дизайнере (с 0.26.0; действие `Zelda: Message Style`, показывавшее их диалогом PS Maker, удалено):

1. `Zelda: UI Layout` с именем экрана (например, `message`), **Role** → *Message box*.
2. Панель-картинка и **Text** с текстом `{message}` и галочкой **Wrap lines at the width** — сюда печатается сообщение.
3. **Shows these messages**: таблички и тексты объектов; полученные предметы (из сундуков, большие предметы); подсказки («Заперто», «Нужен ключ», «Слишком тяжело»); короткие заметки (рупии и прочие мелочи). По умолчанию — таблички и предметы; остальные остаются заметками.
4. **Typing** — сколько букв в секунду печатается (0 — сразу целиком).

Сообщения идут по очереди; пока окно открыто, враги и игрок ждут. Пустая строка в тексте — новая страница. Z, X или Escape: пока текст печатается — показать страницу целиком, потом — следующая страница, на последней — закрыть; щелчок мыши — то же. Для значка «дальше» есть значения `message.ready` (1 — страница напечатана и ждёт клавишу) и `message.more` (1 — дальше есть страницы): например, текст «Z» с эффектом *Blink* и условием *Shown* → *While a value compares* → `message.ready` == 1, как в демо.

`Zelda: Show Message` → **In a message box** — показать свой текст в этом окне (всегда, какие бы виды ни были отмечены); без экрана сообщений — диалогом PS Maker (макет проекта по умолчанию; двоеточия, `@`, `*`, `_` и `{}` экранируются), а если движок диалог показать не может — заметкой.

## Реплики NPC — `Zelda: Dialogue` и экран с ролью *Dialogue box*

С 0.27.0 окно разговора с NPC тоже собирается в дизайнере:

1. `Zelda: UI Layout` с именем экрана (например, `dialogue`), **Role** → *Dialogue box*: панель, табличка с именем — текст `{speaker}`, слова — текст `{message}` с **Wrap lines at the width**, портрет — элемент **Picture** с картинкой *Portrait of the speaker* (`{portrait}`), значок «дальше» по `message.ready`, как у окна сообщений. **Typing** — скорость печати.
2. В событие NPC (например, *Add event trigger* → взаимодействие) — действие `Zelda: Dialogue`: **Speaker**, **Text**, **Portrait** (картинка из Images, по желанию), **Wait until closed**.

Строковое поле PS Maker однострочное, поэтому `\n` в тексте — новая строка, `\n\n` — новая страница. Z, X или Escape: дописать страницу, следующая, на последней — закрыть; пока окно открыто, игра стоит. С **Wait until closed** (по умолчанию) событие PS Maker ждёт, пока игрок закроет окно, и следующие действия события (ещё одна реплика, выдача предмета) идут после. Несколько `Zelda: Dialogue` подряд — разговор из нескольких реплик, можно с разными говорящими.

Без экрана *Dialogue box* реплика показывается в окне сообщений (*Message box*), без него — диалогом PS Maker (с `@name` говорящего, макет проекта по умолчанию), а если движок диалог показать не может — уведомлением «Имя: текст».

**Варианты ответа** (с 0.28.0). В группе **Answers** действия — до четырёх ответов (**Answer 1–4**), у каждого — **Event of answer N**: событие проекта или этой карты (список заполняется событиями проекта и открытой карты), которое запускается, когда игрок выбрал этот ответ. **Answer variable** (по желанию) получает выбранный ответ: номер (1–4) — в числовую переменную, текст — в текстовую. Ответы появляются, когда последняя страница напечатана: стрелки двигают выбор, Z или щелчок выбирает, X и Escape вопрос не пропускают. С *Wait until closed* событие PS Maker продолжается после того, как закончилось событие ответа, — так строится ветвящийся разговор: событие ответа может содержать свои `Zelda: Dialogue` с ответами.

Как ответы выглядят, задаёт элемент **Choice list** в окне диалога: шрифт, размер, цвета обычного и выбранного ответа, текст перед выбранным, высота строки, зазор, картинки строки и выбранной строки (9-slice). Без него ответы печатаются строками под текстом (выбранный — с `>`). В окне сообщений ответы тоже работают; без окон Toolkit (диалог PS Maker) ответы не выбрать — в консоли предупреждение.

Для сцен со штатными портретами-анимациями и макетами PS Maker остаются **Dialogue** и **Choices** PS Maker (их вид — Game UI → Dialogue layouts, Choice layouts). Пока открыт диалог PS Maker, Toolkit стоит на паузе (`combat.pauseDuringDialogue`).

## Уведомления — экран с ролью *Notifications*

Короткие уведомления Toolkit — «Получено: Бомбы ×5», «Сохранено», подсказки и всё, что не показывает окно сообщений, — без такого экрана рисует встроенная плашка. С 0.27.0 их можно собрать в дизайнере: `Zelda: UI Layout` с именем экрана (например, `notification`), **Role** → *Notifications*, плашка-картинка и текст `{note}`. Каждое уведомление рисуется этим макетом, пока не выйдет его время (`ui.messageMs`, у `Show Message` — *Duration*); одновременно до трёх, каждое следующее — на высоту макета дальше от края экрана, у которого макет стоит (у верхнего — вниз, у нижнего — вверх). Игра под уведомлениями идёт, клавиши им не нужны.

**Если проект собран до 0.26.0.** Оставшийся `Zelda: Message Style` PS Maker в игре пропускает (в консоли — `No plugin action handler found for: plugin:zelda-maker-toolkit:zelda-message-style`), и сообщения становятся заметками. Удалите его и сделайте экран сообщений.

## Экран управления — элемент *Key bindings* (с 0.32.0)

Игрок сам меняет клавиши и кнопки геймпада, как во внутриигровых меню управления:

1. Экран (например, `controls`, роль *Plain*), в нём элемент **Key bindings** — с 0.36.0 сначала ходьба (**Вверх, Вниз, Влево, Вправо**), затем строка на каждое действие Toolkit (меч, предмет 1 и 2, щит, действие, следующий и предыдущий предмет, предметы, пауза) с его клавишей и кнопкой геймпада. Строки, которые не помещаются в элемент, прокручиваются вместе с выбором (стрелочки сверху и снизу показывают, что есть ещё); кнопка с действием **Reset the player's controls** и кнопка **Close this screen**. Откройте экран кнопкой меню паузы (*Open a screen*).
2. В игре: стрелки выбирают строку и столбец (клавиатура или геймпад), Z — ждать новую клавишу (или кнопку мыши) либо кнопку геймпада; Escape отменяет (кроме строки «Пауза»). Клавиша, которая уже была у другого действия, меняется с ним местами. Вниз от последней строки — к кнопкам экрана.
3. Выбор игрока хранится в браузере (localStorage, отдельно для каждого проекта) и ложится поверх управления проекта (`Start Toolkit`, `Set Controls`) на каждой карте. *Reset* возвращает управление проекта.
4. **Ходьба и взаимодействие — клавиши самого PS Maker** (с 0.36.0). Свою клавишу для «Вверх» и т.д. (и для «Действия», которое у PS Maker — *Interact*: говорить, триггеры взаимодействия) Toolkit передаёт PS Maker как его собственную: игрок жмёт K — PS Maker получает свою клавишу «Вверх». Прежняя клавиша PS Maker («стрелка вверх») после этого не двигает. У геймпада для ходьбы остаются крестовина и стик. Подробности — ENGINE_AUDIT, раздел 30. Не меняется так: клавиша, которой листается диалог PS Maker (это всегда и его клавиша *Interact*, и клавиша, которую выбрал игрок), и клавиши своих управлений проекта (*Controls* PS Maker).
5. Пока открыт экран Toolkit, который принимает клавиши (пауза, настройки, диалог Toolkit…), PS Maker не получает клавиш ходьбы и взаимодействия (с 0.36.0): нажатие в меню больше не заговаривает с NPC перед игроком.

**Подсказки клавиш.** В тексте `{key:sword}` — клавиша действия сейчас (`{key:useItem}`, `{key:shield}`, `{key:up}`…). Если игрок последним нажимал геймпад, это кнопка геймпада с его названиями: A/B/X/Y и LB/RB у Xbox (и Steam Deck), Cross/Circle/Square/Triangle и L1/R1 у PlayStation, B/A/Y/X и L/R у Nintendo — тип геймпада определяется по его имени. Кнопки мыши и стрелки подписываются словами на языке игры.

## Инвентарь — экран с ролью *Inventory*

`Zelda: UI Layout` с именем экрана, **Role** → *Inventory*, и в нём элемент **Inventory grid** — предметы игрока сеткой в порядке получения: иконка предмета (свои иконки — в разделе **Item icons**), запас у бомб и стрел, курсор (картинка *Cursor picture* или золотая рамка). I открывает этот экран вместо встроенной панели. Стрелки двигают курсор по сетке, Z, C или щелчок по клетке ставят предмет на первую кнопку предмета, B — на вторую (с 0.29.0; меч и щит на кнопки не ставятся, у них свои клавиши), I, X или Escape закрывают. Тексты показывают предмет под курсором: `{inv.name}`, `{inv.description}` (с **Wrap lines at the width**), `{inv.count}`.

Без такого экрана I открывает встроенную панель (её фон и курсор — в разделе **Layout** HUD).

## Главное меню

Титульного экрана в PS Maker нет: игра начинается со стартовой карты. Сделайте её меню (так в демо с 0.26.0):

1. Карта «Title» — стартовая (Player → Starting map).
2. «Map setup»: **Set player visibility** → Hide, **Toggle player movement** → Disable.
3. «Map start»: `Zelda: UI Layout` с именем экрана (например, `title`) и **Role** → *Title*: название, кнопки; затем `Zelda: Open UI Screen` с этим именем.
4. Кнопки — *Run a PS Maker event* с глобальными событиями:
   - «Новая игра» → **Change map** на первую игровую карту;
   - «Продолжить» → **Open load game menu**;
   - «Настройки» → **Open game options menu** (без кнопки сохранения);
   - «Выход» → **Exit game**.

Пока титульный экран открыт, HUD скрыт, клавиши назад его не закрывают, а Escape остаётся у PS Maker. Когда игрок возвращается на титульную карту (например, кнопкой меню паузы), PS Maker будит её без «Map start», а Toolkit открывает титульный экран снова (с 0.26.1).

Можно и по-старому — **Add UI** PS Maker с кнопками без Toolkit на титульной карте; стиль кнопок — Game UI → Button styles.

## Настройки

Меню опций PS Maker ставит игру на паузу; Toolkit стоит вместе с ней. Открывается оно Escape, а если в проекте есть меню паузы Toolkit — его кнопкой (событие с **Open game options menu**). Клавиши, нажатые в меню, после закрытия не срабатывают (меч не взмахнёт). Звуки Toolkit (`Zelda: Set Sound`) следуют ползунку **Sound Volume**, как звуки самого PS Maker.

## Сохранения PS Maker и прогресс Toolkit

PS Maker сохраняет позицию, переменные и состояние карт, а прогресс Toolkit (открытые сундуки, предметы, сердца, ключи) — нет. Свяжите их:

1. Создайте **текстовую** глобальную переменную, например «Zelda progress».
2. `Zelda: Start Toolkit` → **Progress variable** — выберите её (Start Toolkit один на проект).

Toolkit держит в переменной свой прогресс. Когда PS Maker загружает сохранение и меняет переменную, Toolkit восстанавливает прогресс из неё. Когда переменная снова пустая (новая игра), Toolkit начинает сначала.

**Загрузка.** Карта, восстановленная из сохранения, не выполняет «Map setup» / «Map start» заново (так устроен PS Maker 1.2.1). Toolkit замечает такую карту и сам выполняет её действия `Zelda:`, которые строят карту (Start Toolkit, объекты, враги, правила, стили), без разовых эффектов вроде Give Item.

## Дополнительно: значения Toolkit в Add UI — `Zelda: Show Stat In Variable`

HUD Toolkit (дизайнер выше) покрывает обычный случай. Если нужна своя надпись или шкала из компонентов PS Maker, `Zelda: Show Stat In Variable` держит значение Toolkit в переменной проекта: рупии, бомбы, стрелы, ключи, сердца (все, целые, половинка 1/0), здоровье, магия (в том числе в %), имя и боезапас выбранного предмета, «предмет выбран» и «предмет есть» (1/0). Свойства компонентов Add UI берут значение из переменной или выражения (`@{переменная}`, `+ − * /`, скобки) — без сравнений и округления, поэтому Toolkit отдаёт готовые целые числа. PS Maker рисует картинки интерфейса в логических пикселях игры (обычно 1280×720): при масштабе карты 4 картинку 9×8 надо рисовать вчетверо крупнее.
