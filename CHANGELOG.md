# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [0.36.0] — 2026-10-31

### Добавлено
- **Игрок меняет и клавиши ходьбы** (просил пользователь): на экране «Управление» (элемент *Key bindings*) первыми идут «Вверх, Вниз, Влево, Вправо». Это клавиши самого PS Maker. Toolkit подставляет PS Maker его клавишу вместо выбранной игроком, а от прежней отказывается: стрелка больше не ходит, если игрок выбрал другую (ENGINE_AUDIT, раздел 30). Своя клавиша «Действия» становится и клавишей взаимодействия PS Maker (говорить, триггеры). Геймпад для ходьбы оставляет крестовину и стик.
- Строки элемента *Key bindings*, которые не помещаются, прокручиваются вместе с выбором; стрелочки показывают, что есть ещё.
- Клавиши обмениваются между всеми строками, в том числе между ходьбой и действиями. Вторая клавиша другой строки, если её забрали, у той строки просто убирается.

### Исправлено
- **Нажатие в меню Toolkit доходило до PS Maker**: Z (или Enter) в меню паузы рядом с NPC открывал его диалог через взаимодействие PS Maker. Теперь, пока открыт экран Toolkit, принимающий клавиши, PS Maker клавиш ходьбы и взаимодействия не получает.

### Изменено
- **Toolkit — один раз на проект** (просил пользователь):
  - `Zelda: Start Toolkit` ставится в «Map start» одной карты, и Toolkit сам запускается на каждой карте проекта — также на картах без единого действия Toolkit и после загрузки сохранения;

- **Сохранение и загрузка — в меню паузы, а не в настройках** (просил пользователь): демо — пауза *Продолжить, Сохранить игру, Загрузить игру, Настройки, Главное меню*; управление — в настройках.
- Демо: `Start Toolkit` и `Set Player Sprites` только на первой карте (на подземелье и титуле их больше нет).

## [0.33.0] — 2026-10-30

Просил пользователь: возможности, как у Non-Destructive Localization (Sang Hendrix) для RPG Maker MZ/MV, — по скриншоту его страницы; код и данные плагина не использовались. Подробно — [docs/TRANSLATIONS.md](docs/TRANSLATIONS.md).

### Добавлено
- **`Zelda: Translations`** — переводы игры без правки текстов. Таблица в проекте: строка на текст, столбец на язык. Первый язык — тот, на котором написан проект.
- **Таблица переводов в редакторе** (панель справа, пока действие открыто):
  - **Find texts in the project** собирает всё, что видит игрок: страницы и имена в *Dialogue* PS Maker, *Choices*, картинки *Show Image* / *Change Image*, сообщения, таблички, реплики и ответы `Zelda: Dialogue`, названия предметов, тексты макетов UI и строки самого Toolkit. Повторный поиск сохраняет переводы, а тексты, которых больше нет в проекте, оставляет с пометкой;
  - поиск по таблице и фильтры (не переведено, не в проекте, по типу);
  - языки: добавить, переименовать, удалить; свой макет диалога и выбора PS Maker и шрифт Toolkit для языка;
  - Undo и пять резервных копий в браузере перед поиском и импортом.
- **CSV для Excel и Google Sheets.** Экспорт через окно сохранения настольного редактора, в веб-редакторе — скачиванием. UTF-8 с BOM. Разделитель «;» или «,» выбирается по языку системы или вручную. При импорте разделитель определяется сам, новые языки добавляются.
- **Перевод во время игры.** *Dialogue*, *Choices*, *Show Image* и *Change Image* PS Maker переводятся в момент выполнения, а действия в проекте остаются как написаны (ENGINE_AUDIT, раздел 27). Команды диалога сохраняются. Строку перевода, похожую на команду или «Имя: текст», Toolkit экранирует.
- **Язык игры.** *Language* у `Start Toolkit` теперь принимает и языки таблицы (*Auto* — язык браузера, если он есть в таблице). Кнопка экрана **Change the language** переключает язык (на следующий или по коду), выбор игрока хранится в браузере. `{language}` в макете — название языка. Событие `zelda:language:changed`.
- **Демо**: русский перевод всего демо (в браузере на русском оно идёт по-русски), кнопка *Language* в меню паузы, прощание жителя — диалог самого PS Maker.

### Изменено
- `config.language` — любой код языка, не только `auto` / `en` / `ru`.
- Рантайм-проверка: в русском браузере демо идёт по-русски, ожидания проверок — русские тексты.

## [0.32.0] — 2026-10-30

Просил пользователь: возможности, как у Keyboard Gamepad Solution (Sang Hendrix) для RPG Maker MZ — по скриншоту его страницы; код и данные плагина не использовались.

### Добавлено
- **Геймпад без плагинов**: Toolkit читает геймпады через браузерный Gamepad API (Xbox, PlayStation, Nintendo, Steam Deck — стандартная раскладка; несколько сразу). Кнопки и левый стик становятся нажатиями клавиш, поэтому на геймпаде играет и сам PS Maker (движение, взаимодействие), и Toolkit, и триггеры PS Maker по клавише (ENGINE_AUDIT, раздел 26).
- **Любая кнопка геймпада — любая клавиша**: `Zelda: Set Controls` → *Gamepad: extra buttons* (до четырёх пар кнопка → клавиша; `controls.gamepad.extra`). Вместе с *Add event trigger* → *Keyboard* в PS Maker это запуск события по кнопке геймпада. Кнопки геймпада для действий Toolkit — там же, группа *Gamepad*.
- **Мышь**: `MouseLeft`, `MouseRight`, `MouseMiddle` в клавишах действий Toolkit (как в PS Maker); с правой кнопкой браузерное меню над игрой отключается.
- **Экран управления для игрока**: элемент дизайнера *Key bindings* — действия Toolkit с клавишами и кнопками геймпада; игрок меняет их сам (клавиша, кнопка мыши или кнопка геймпада; занятая меняется местами), выбор хранится в браузере для этого проекта и лежит поверх управления проекта; кнопка с действием *Reset the player's controls* возвращает его.
- **Подсказки клавиш** `{key:sword}` в текстах: клавиша действия, а после нажатия геймпада — его кнопка с названиями Xbox, PlayStation (Cross, Circle…) или Nintendo, по типу подключённого геймпада.
- Демо: в меню паузы кнопка *Controls* — экран управления (Reset, Back).

### Изменено
- Чтение геймпада через плагин Phaser Gamepad убрано: работает браузерный Gamepad API.

## [0.31.0] — 2026-10-30

Просил пользователь: сделать крюк-кошку и подбор брошенной бомбы.

### Добавлено
- **Крюк-кошка** (`hookshot`; снова, на новом коде): крюк на цепи летит вперёд. Враг — урон и оглушение; выпавший предмет крюк приносит игроку; за столб (новый объект `hook_post`), сундук, блок, камень, горшок, табличку, факел или рычаг (`items.hookshot.grabs`) крюк цепляется и подтягивает игрока, над ямами; стена — искра, крюк возвращается. Пока крюк летит, игрок стоит. Тип урона `hookshot`, событие `zelda:hookshot:grabbed`.
- **Подбор бомбы**: положенную бомбу поднимают клавишей действия и бросают второй; фитиль горит и в руках — не бросил вовремя, взорвётся над головой. Удар по игроку роняет бомбу к ногам.

### Изменено
- Демо: крюк-кошка в сундуке на поле; на уступе с переключателем — столб, к которому крюк перетягивает через ямы (второй путь к переключателю, кроме бумеранга).

## [0.30.0] — 2026-10-30

Просил пользователь: сделать и остальные предметы — лопату, порошок, бомбо-стрелы.

### Добавлено
- **Лопата** (`shovel`): копает перед игроком. Закопанный клад выкапывается, на обычной земле — дроп по шансу (`items.shovel.drops`), ямка видна несколько секунд; в стену и твёрдые объекты лопата не входит.
- **Закопанный клад**: `Zelda: Create Chest` → **Buried** — невидимое место с предметом; выкопанное остаётся ямкой и сохраняется в прогрессе. Событие `zelda:object:dug`, для обычной земли — `zelda:ground:dug`.
- **Волшебный порошок** (`magic_powder`, ресурс `powder`, ёмкость 20): облако перед игроком ранит и оглушает врагов, зажигает факелы и сжигает кусты. С предметом приходит 10 порошка; `powder` в `Give Item` — пополнение.
- **Бомбо-стрелы**: лук и бомбы на двух кнопках предметов, нажатые вместе, — стрела, которая взрывается как бомба (стена, враг, объект, конец полёта); тратит стрелу и бомбу.
- Иконки и спрайты новых предметов нарисованы кодом.

### Изменено
- Взрыв бомбы вынесен в общую функцию (`explodeAt`): так же взрываются бомбо-стрелы.
- Демо: житель на «Any advice?» дарит лопату и говорит, где закопан волшебный порошок (под местом старта) и как стрелять бомбо-стрелой.

## [0.29.0] — 2026-10-30

Просил пользователь: чтобы щит и остальные предметы работали как в ремейке *The Legend of Zelda: Link's Awakening*. Перенесены механики (своими словами и своим кодом), картинки и звуки игры не используются: иконки новых предметов нарисованы кодом.

### Добавлено
- **Две кнопки предметов**: C и B (`controls.useItem2`, геймпад — кнопка 3). В экране инвентаря C или Z ставят выбранный предмет на первую кнопку, B — на вторую; предмет с другой кнопки меняется местами. Новый предмет сам встаёт на свободную кнопку. `Zelda: Equip Item` получил поле *Item button*. *Item box* в дизайнере — поле *Item button*; классический HUD показывает обе кнопки.
- **Щит**: с поднятым щитом игрок идёт медленнее (`shield.walkSpeed`, через скорость игрока PS Maker) и смотрит в ту же сторону, отступая боком и назад (`shield.lockFacing`); враг, наткнувшийся на щит спереди, отлетает (`shield.bashKnockback`), игрок урона не получает.
- **Зеркальный щит** (`mirror_shield`): держится той же клавишей и отражает выстрелы и магию обратно — они летят во врагов, в том числе в стрелка.
- **Сапоги-скороходы** (`boots`): держать кнопку предмета — разбег на месте с пылью, затем рывок вперёд, пока кнопка нажата; с мечом он выставлен вперёд и бьёт врагов, кусты и траву; стена или камень — отскок назад.
- **Перо Рока** (`feather`): прыжок — игрок нарисован выше с тенью на земле, ямы, шипы и наземные враги в воздухе не действуют; приземление на яму — падение; прыжок во время рывка сохраняет скорость (длинный прыжок).
- События `zelda:player:reflected`, `zelda:player:jumped`, `zelda:player:dashed`, `zelda:player:bumped`.

### Изменено
- Демо: сапоги и перо в сундуках в верхнем ряду поля; HUD демо показывает вторую кнопку под первой; подсказка на табличке.

## [0.28.0] — 2026-10-30

Просил пользователь: сделать в диалогах то, чего не хватало (выбор ответа), и чтобы HUD был такой же ролью, как остальные, без «каши».

### Добавлено
- **Варианты ответа в `Zelda: Dialogue`**: до четырёх ответов, у каждого — событие PS Maker, которое запускается при выборе; выбранный ответ можно сохранить в переменную (номер или текст). Ответы появляются после последней страницы: стрелки, Z или щелчок; X и Escape вопрос не пропускают. Событие PS Maker ждёт и выбора, и события ответа — разговор может ветвиться дальше.
- Элемент **Choice list** для окна диалога: как выглядят ответы (шрифт, цвета, строки-картинки 9-slice, текст перед выбранным). Без него ответы печатаются строками под текстом.

### Изменено
- **HUD — обычная роль.** Что это за макет, решает только его роль; смена роли больше не трогает поле *Screen name*. Как и у всех ролей, в проекте работает первый макет роли по порядку карт, а про остальные дизайнер пишет одинаковой плашкой «Not used in the game». *Screen name* — только имя для `Open UI Screen` и кнопок. Макет без имени и без роли (HUD до 0.28.0) по-прежнему HUD.
- `runStoryEvent` хоста возвращает обещание окончания события (нужно, чтобы диалог ждал событие ответа).
- Демо: житель после двух страниц спрашивает «Any advice?» / «Bye!»; первый ответ запускает событие проекта «Villager: advice» с его советом.

## [0.27.0] — 2026-10-30

Спросил пользователь: куда из ролей делся HUD; хотелось бы дизайнить и все всплывающие уведомления, и диалоговое окно с NPC, а не только табличку.

### Добавлено
- **HUD в списке ролей** дизайнера. HUD — это `UI Layout` без имени экрана: выбор у HUD другой роли записывает имя экрана в поле **Screen name** действия, выбор *HUD* у экрана очищает его.
- **Роль *Dialogue box* и действие `Zelda: Dialogue`**: реплика NPC в окне из дизайнера — `{speaker}`, `{message}` с печатью и страницами, портрет (элемент Picture с картинкой `{portrait}`). Событие PS Maker ждёт, пока игрок закроет окно (*Wait until closed*), так что реплики и другие действия идут по очереди. `\n` в тексте — новая строка, `\n\n` — страница. Без окна диалога — окно сообщений, без него — диалог PS Maker с именем говорящего.
- **Роль *Notifications***: каждое короткое уведомление («Получено: Бомбы ×5», «Сохранено», подсказки) рисуется макетом из дизайнера с текстом `{note}`, пока не выйдет его время; несколько — стопкой; игра идёт.
- Картинка элемента Picture может быть значением: `{portrait}`.

### Изменено
- Демо: житель говорит через `Zelda: Dialogue` в окне с табличкой имени; уведомления — плашкой под HUD; оба экрана собраны в дизайнере.

## [0.26.1] — 2026-10-30

## [0.6.0] — 2026-10-25

По исходному коду рантайма PS Maker 1.2.1 из экспорта игры (source maps), см. `docs/ENGINE_AUDIT.md`, раздел 11.

### Исправлено — главная причина «враг не появляется»
- PS Maker выполняет действия события по очереди и **ждёт `ctx.endAction()`** от каждого. Действия Toolkit его не вызывали, поэтому событие останавливалось на `Start Toolkit`, а `Create Enemy` и всё после него не выполнялось. Теперь каждое действие завершает себя (и при ошибке). Опубликованные типы `@ps-maker/plugin-api@0.0.3` этого требования не описывают.

### Изменено: штатные виджеты PS Maker
- *Position* — тип `map-position`: кнопка выбора точки на карте, как у встроенных событий.
- Выпадающие списки (`string-enum`): сложность, язык, шаблон врага (+ поле *Custom template* для своих), тип объекта, замок двери (вместо трёх галочек), операция `Change Object`, тип урона, момент звука, ресурс предмета.
- `Enemy From NPC` — список NPC на карте (`in-map-npc`).
- `Set Player Sprites` — выбор анимации игрока из PS Maker (`player-animation-picker`) для атаки и урона вместо галочки 0.5.2.
- Сохранённые старыми версиями значения (числовая сложность, галочки замка, галочка 0.5.2) продолжают работать.

### Добавлено
- Бой сам встаёт на паузу, пока на экране диалог PS Maker (`GameMap.playingDialogue`); `combat.pauseDuringDialogue`.
- Анимации из PS Maker берутся из его собственных текстур (`<id анимации>frames`), номера кадров — по ширине картинки, как в PS Maker.
- Поиск NPC по `inGameCharacterId`.

### Удалено
- Запуск действий из данных карты (0.5.3) — обход больше не нужен.
- Плагин-зонд `tools/param-probe` — вопрос о типах полей решён по исходному коду.
