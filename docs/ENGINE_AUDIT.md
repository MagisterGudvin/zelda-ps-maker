### Расхождение `defineEvent` vs `defineAction`

Опубликованный пакет `@ps-maker/plugin-api@0.0.3` и все шаблоны CLI используют
`defineEvent({...})` и поле `events` в `definePlugin`. Поисковый сниппет
веб-документации упоминает `defineAction`. Последняя версия пакета на npm — `0.0.3`,
и официальный CLI собирает бандл, **встраивая** (inline) реализацию из
`@ps-maker/plugin-api/dist/empty.js` (identity-функции). Значит, во время выполнения
PS Maker получает просто объект `export default { name, description, version, events }`.

Решение: Toolkit использует подтверждённый пакетом формат (`defineEvent` / `events`).
Если редактор новой версии ожидает поле `actions`, совместимость обеспечивает
`src/editor/pluginShape.ts`: экспортируемый объект содержит и `events`, и `actions`
(ссылки на один и тот же массив). Это задокументированное предположение, которое
нужно проверить в реальном PS Maker (сценарий `M-01` в `docs/TESTING.md`).

## 1. Как устроена система плагинов (подтверждено)

Источник: `node_modules/@ps-maker/plugin-api/dist/pluginAPI.d.ts`,
`node_modules/@ps-maker/plugin-cli/dist/index.js` (исходник —
`ps-maker-plugin-cli/src/commands/build.ts`).

1. **Формат файла.** ES-модуль, один бандл `dist/<kebab-name>.ps-maker.js`
   (`esbuild`, `bundle: true`, `format: "esm"`, `platform: "browser"`,
   `target: "es2020"`, `minify: true`). Внешних модулей во время выполнения нет:
   всё, кроме типов, встраивается в бандл.
2. **Точка входа** — строго `src/index.ts`. CLI регулярным выражением
   `definePlugin\s*\(\s*\{[^}]*name:\s*["']…["']` извлекает `name` и `version`
   из исходника, поэтому `name`, `description`, `version` должны быть строковыми
   литералами **до первой `}`** внутри вызова `definePlugin`. `version` обязан быть
   валидным semver, иначе сборка падает.
3. **Плагин** = `{ name, description, version, events: PluginEvent[] }`.
4. **Событие (действие редактора)** = `{ name, description, parameterDefs, execute }`.
   Имя показывается в редакторе событий PS Maker; `parameterDefs` автоматически
   генерирует форму настройки в редакторе.
5. **Типы параметров** (`ParamSchema`): `string`, `number`, `boolean`
   (с `defaultValue`), `position`, `image`, `audio`, `npc` (без `defaultValue`,
   тип значения во время выполнения — `any`, формат не документирован).
   Поле `label` используется в шаблонах CLI, но отсутствует в типах `0.0.3`
   (поэтому Toolkit передаёт его через приведение типа — оно безвредно, если
   редактор его игнорирует).
6. **Обработчик** `execute(params, ctx): void` вызывается, когда событие
   «проигрывается» в цепочке событий PS Maker. Он **синхронный** по типу; ожидает ли
   редактор Promise — не задокументировано, поэтому Toolkit всегда возвращает
   управление сразу.
7. **Контекст** `PluginContext`:
   - `game: Phaser.Game` (комментарий: «StoryGame extends Phaser.Game», то же, что
     `window.game`);
   - `scene: any` — «текущая активная GameMap scene (extends Phaser.Scene)»;
   - `player: any` — «Actor (extends Phaser.Physics.Arcade.Sprite)».
8. **Установка**: файл `*.ps-maker.js` кладётся в `/plugins` проекта.

### Чего в API НЕТ (подтверждено отсутствием в `pluginAPI.d.ts`)

- хуков жизненного цикла (`onLoad`, `onUnload`, `onMapChange`, `onSave`);
- регистрации **условий** (conditions) для ветвления событий PS Maker;
- доступа к переменным/флагам PS Maker, к встроенному инвентарю и к сохранениям;
- API для отправки событий *из* плагина в систему событий PS Maker (запустить
  группу событий, установить переменную);
- регистрации собственных панелей/вкладок редактора;
- объявления параметров-списков (enum), массивов или вложенных объектов.

## 4. Минимальный MVP без изменения ядра

1. Бандл `dist/zelda-maker-toolkit.ps-maker.js`, кладётся в `/plugins`.
2. On-load события карты: `Zelda: Start Toolkit` → `Zelda: Create Enemy` /
   `Zelda: Create Object` / `Zelda: Create Chest` / `Zelda: Add Rule`.
3. Меч, здоровье, урон, отбрасывание, неуязвимость, бомба, бумеранг, лук, щит,
   магия, инвентарь с быстрым слотом, HUD, сундук/ключ/дверь, блок+плита,
   сохранение в `localStorage`.

Ядро PS Maker не изменяется. Глобальное состояние: единственное свойство
`globalThis.ZeldaMakerToolkit` (можно отключить) — публичный API для
плагинов-расширений (собственные предметы/враги/условия).

## 5. Поведение ALttP, изученное по zelda3 (без переноса кода)

| Механика | Наблюдение в zelda3 | Реализация в Toolkit |
|---|---|---|
| Неуязвимость игрока | `countdown_for_blink = 58` кадров после урона; урон не принимается во время мигания (`player.c`, `Link_ControlHandler`). | `player.invulnerableMs = 970` по умолчанию, мигание спрайта. |
| Смерть игрока | Здоровье ≤ 0 → модуль Game Over; восстановление по таблице `kHealthAfterDeath`. | Состояние `dead`, событие `zelda:player:died`, возрождение с `respawnHealth` в точке возрождения. |
| Удар мечом | Последовательность кадров удара с задержками `kSpinAttackDelays`; направление фиксируется на время удара (`link_cant_change_direction`). | Фазы windup/active/recovery, фиксация направления, хитбокс только в active. |
| Заряд и круговой удар | Удержание кнопки после удара, счётчик `link_spin_attack_step_counter` до 48 кадров; удар по врагу во время заряда сбрасывает заряд («тычок»). | `chargeMs = 800`, spin-атака при отпускании, опциональный тычок при заряде. |
| Повторный урон | `sprite_hit_timer` — враг не получает урон, пока таймер не истёк. | У цели `hitCooldownMs` + у атаки реестр `hitId → число попаданий` (`maxHitsPerTarget`). |
| Отбрасывание | `sprite_x_recoil/sprite_y_recoil` — скорость отдачи от направления удара; гасится со временем. | `knockback` вектор с затуханием и столкновением со стенами. |
| Бомба | Фитиль `kBomb_Tab0[0] = 0xA0` (160 кадров ≈ 2.7 с), урон проверяется по спрайтам в радиусе, отбрасывание. | `fuseMs = 2600`, радиус, урон, разрушение подходящих объектов. |
| Производительность | Проверки урона распределены по кадрам: `(j ^ frame_counter) & 3`. | ИИ врагов принимает решения раз в N тиков со сдвигом по id; движение — каждый тик; один общий цикл обновления. |
| Классы урона | Таблицы урона по типу оружия и врагу (`kEnemyDamages`, `damage_type_determiner`). | Таблица типов урона + сопротивления врага (множители, 0 = иммунитет). |
| Бумеранг | Оглушает врагов, возвращается, один активный бумеранг. | `stunMs`, возврат к игроку, `maxActive`. |

## 6. Референс Sang Hendrix (RPG Maker MZ)

Доступны только публичные ответы автора на форуме itch.io: враги помечаются тегом
`<enemy>` на событии карты, контактный урон проверяется общей функцией с задержкой
между попаданиями (`checkCollide('player', '<enemy>', 15)`), полоса здоровья врага
связывается с базой врагов по имени. Принципы, которые взяты: (а) враг — это обычный
объект карты движка, помеченный конфигурацией; (б) контактный урон с кулдауном;
(в) настройка через параметры, а не код. API RPG Maker не используется: в PS Maker
его нет.

## 10. Файл проекта PS Maker 1.2.1 (story.json, 2026-10-25)

Пользователь прислал файл проекта (`metadata.psMakerVersion` 1.2.1, `schemaVersion` 32). В репозиторий он не добавлен; ниже — только то, что в нём установлено.

**Действия плагинов в событиях карты**
- Карта: `maps[]` с `id` (он же ключ сцены Phaser, например `first-map-rakjdawa`), `tileSize`, списками `setupActions`, `initialActions`, `enterActions`, `leaveActions`. Действия Toolkit пользователя лежат в `initialActions`.
- Действие плагина: `{ "type": "plugin:zelda-maker-toolkit:zelda-create-enemy", "pluginName": "Zelda Maker Toolkit", "actionName": "Zelda: Create Enemy", "pluginParams": { ... } }`. Ключ строится из имён плагина и действия, поэтому **переименование действия ломает сохранённые проекты** — имена закреплены тестом.
- В `pluginParams` хранятся только поля, которые есть в форме на момент сохранения. **Нетронутое поле Position не сохраняется вовсе** (в присланном проекте у `Create Enemy` нет ключа `position`). С 0.5.1 враг без Position ставится рядом с игроком с предупреждением.
- На карте нет ни одного NPC (`mapObjects` пуст) — значит, прежний выбор *Use NPC* = Slime ссылался на ассет персонажа, которого на карте нет. Это согласуется с тем, что PS Maker пропускал действие, но причину пропуска файл не показывает.

**Персонажи и анимации**
- `characters[]`: `id`, `name`, `key`, `animationSets[]` с направлениями (`down/up/left/right`, `idleDown…`), `collision.box` в пикселях кадра, `depthOrigin`, `movementSpeed`.
- `spritesheetAnimations[]`: лист (`src` — имя файла ассета, `frameWidth/Height`, `frameRate`, `format: "horizontal-frames"`, `ownerRef` — персонаж или игрок), внутри — диапазоны кадров по строкам. Для наборов Mana Seed строки: 0 вниз, 1 влево, 2 вправо, 3 вверх (из набора анимаций по умолчанию).
- У игрока свои листы (`ownerRef.type: "player"`), у пользователя: Sword Attack, Sword Hurt, Sword Walk и др.; у персонажа Slime — Slime Run/Idle/Attack/Hurt/Death.
- Объекты карты (`mapObjects` уровня проекта) имеют `collision.box` и `depthOrigin`; у тестовой карты объектов и коллизий нет — поэтому в диагностике «0 static bodies».
- Тайлы ландшафта адресуются и отрицательными индексами: отрицательные координаты на картах PS Maker — норма.

**Что из этого сделано (экспериментально)**
- Выпадающий список *Look (PS Maker character)* (тип `npc`) у `Create Enemy` и галочка *Use the player's PS Maker animations* у `Set Player Sprites`: анимации и коллизия берутся из данных проекта. Формат значения поля `npc` не задокументирован — принимаются id, имя, объект с ними или игровой объект; что именно пришло, видно в журнале диагностики (`Create Enemy {...}`). Плагину API эти данные не передаёт, поэтому Toolkit ищет их во время игры (JSON-кэш Phaser, реестр, свойства сцены и игры; поиск ограничен по глубине и числу узлов) и пишет в диагностике, где нашёл: `PS Maker data: …`. Текстуру листа ищет по id, имени файла или URL картинки. **В самом PS Maker не проверено**, где лежат эти данные во время игры; если строка диагностики говорит «not reachable», остаются `Define Sprite Sheet` / `Define Animation`.

**Что ещё нужно для подтверждения:** экспорт игры (Web) — по нему видно, как движок выполняет `initialActions` и вызывает плагины, где хранит данные проекта и под какими ключами грузит текстуры.

**Playtest 0.5.2 (2026-10-25).** Данные проекта во время игры лежат в `scene.sys.settings.data.story` (подтверждено строкой диагностики `PS Maker data: scene.data.story (13 characters, 65 sheets)`). PS Maker вызвал `Start Toolkit` пять раз (каждый запуск сцены), а сохранённый следом `Create Enemy` — ни разу, ошибок и предупреждений нет. Причина в коде событий PS Maker остаётся неизвестной (нужен экспорт игры). Обход с 0.5.3: Toolkit сам выполняет действия `Zelda:`, сохранённые сразу после `Start Toolkit`, если PS Maker не вызвал их за 0,5 с.

## 11. Исходный код рантайма PS Maker 1.2.1 (экспорт игры, 2026-10-25)

Пользователь прислал экспорт игры для Web. В нём есть source maps с исходным кодом рантайма (`src/lib/...`). Код прочитан для совместимости; в плагин он **не копировался**, экспорт в репозиторий не добавлен. Ниже — установленные факты со ссылками на файлы рантайма.

**Как PS Maker выполняет действия плагина** (`game/story/StoryRunner/StoryRunner.ts`, `features/pluginSystem/*`)
- Действия одного события выполняются по очереди; **каждое должно вызвать `ctx.endAction()`**, иначе событие ждёт бесконечно («An action that never calls it leaves its event waiting»). Опубликованные типы `@ps-maker/plugin-api@0.0.3` об этом не говорят. **Это и было причиной** того, что после `Start Toolkit` не выполнялся `Create Enemy`: действия Toolkit не вызывали `endAction`. Исправлено в 0.6.0 — каждое действие завершает себя, в том числе при ошибке.
- `endAction({ stopEvent: true })` останавливает текущее событие, `{ stopAllEvents: true }` — все события карты.
- Контекст: `{ game, scene (GameMap), player, endAction, signal (AbortSignal), … }`.
- Параметры приходят **как сохранены** (`pluginParams`), без значений по умолчанию; нетронутые поля отсутствуют.
- Ошибка, брошенная из `execute`, ловится PS Maker, пишется в `console.error` и завершает действие.
- Реестр плагинов читает поле **`actions`** (не `events`); тип действия — `plugin:<имя плагина>:<имя действия>` после `sanitizeName` (нижний регистр, пробелы и `:` → `-`).
- Действие плагина может стоять внутри диалога, если у него нет `meta.disableInDialogueAction`.

**Типы полей** (`game/story/StoryActions/api/types.ts`, `ParamType`) — встроенные действия и плагины рисуются одними виджетами. Нужные Toolkit:
| Тип | Виджет | Значение |
|---|---|---|
| `position` | два числовых поля | `{ x, y }` |
| `map-position` | поля + кнопка выбора на карте | `{ x, y }` |
| `string-enum` (+ `options: [{label, value}]`, `ui: "dropdown"`) | выпадающий список | строка |
| `npc` | список персонажей библиотеки | id персонажа |
| `in-map-npc` | список NPC на карте («Spawned NPC») | `inGameCharacterId` |
| `player-animation-picker` | выбор анимации игрока | id анимации |
| `map-rectangle-area` | область на карте | `{ x, y, width, height }` |
| `path` | путь по карте | `[{ x, y }, …]` |
| `string-enum-multi` | множественный выбор | `string[]` |
| `variable` | список переменных проекта | id переменной |
| `key-bindings` | выбор клавиш / управления проекта | `[{ type: "key", key: "KeyX" } \| { type: "control", controlId }]` |
| `animation` | любая анимация проекта | id анимации |
Все они используются Toolkit с 0.7.0. Переменные проекта: `game.variables.get(id)` → `{ type: "boolean" \| "number" \| "string", value }`, `game.variables.set(id, value)`. Что редактор рисует эти типы для плагинов теми же виджетами, подтверждено по коду редактора (раздел 12).

**Карта и персонажи** (`game/Maps/GameMap/*`, `game/classes/*`)
- `GameMap`: `player`, `NPCs` (у NPC — `inGameCharacterId`), `collisions` (прямоугольники `GameMapCollision` со статическими телами Arcade и коллайдером с игроком), `story`, `map`, `playingDialogue`.
- Глубина персонажей: `низ спрайта − depthOrigin% × высота` (у игрока из присланного проекта: 84 − 31% × 64 = 64,2 — совпадает с диагностикой).
- Анимации (`game/story/StoryAnimations/loadAnimations.ts`): каждая анимация (строка листа) грузится как текстура всего листа с ключом `<id анимации>frames` и создаётся анимация Phaser с ключом `<id анимации>`; номер кадра = `строка × floor(ширина / frameWidth) + столбец`. Toolkit с 0.6.0 находит текстуры по этому ключу и считает столбцы по ширине картинки.
- Данные проекта во время игры — `scene.sys.settings.data.story`.

## 12. Редактор PS Maker 1.2.1 (сборка из app.asar, 2026-10-27)

Пользователь прислал собранный код редактора (Steam-версия, `resources/app.asar` → `build/_app/immutable/*.js`, `electron/*.cjs`). Source maps в нём нет, код минифицирован; прочитан для совместимости, в репозиторий и плагин не копировался.

**Загрузка плагинов** (`electron/main.cjs`, загрузчик в редакторе)
- Electron только читает файлы `<проект>/plugins/*.ps-maker.js`; редактор импортирует каждый как ES-модуль через blob URL и требует `default` с полями **`name` и `actions`** — плагин только с `events` не загрузится («did not produce a valid Plugin»). Toolkit экспортирует оба поля.
- Ошибка при импорте пишется в консоль «Failed to execute plugin …», плагин пропускается.
- Новое действие получает в `pluginParams` **только поля, у которых есть `defaultValue`** — поэтому нетронутый Position не сохраняется (раздел 10).

**Поля** — один компонент для встроенных действий и плагинов, выбор виджета по `type`; изменение пишется в `pluginParams[ключ]`. При копировании карты поля плагина типов `variable` и `story-event-id` перепривязываются так же, как у встроенных действий.

Свойства поля, которые читает редактор: `label`, `description` (подсказка у названия), `defaultValue`, **`group`** (сворачиваемый раздел), `hidden`, `ui` (`dropdown`, **`radio`**, `checkbox`, `textarea`), `options`, **`min` / `max` / `step`**, `placeholder`, `maxLength`, `rows`, **`required`** (подсветка незаполненного), `nullable`, `setPositionBtnLabel`, `setPathBtnLabel`, **`showPreview`** (показ точки, области или пути на карте редактора: для точек и областей включён по умолчанию, для путей выключен), `fitBoundsInView`, `columnDisplay`, `json`, `showPlayerOption`, `inMapNpcParamKey`, `variableParamKey`, `allowAll`, `allowedSources`, `previewInActionsList`.

Свойства действия: **`parameterVisibility`** (`{ поле: (значения) => boolean }`, значения — сохранённые или `defaultValue`; функции из модуля плагина работают), **`collapsedGroups`** (разделы, свёрнутые при открытии), **`getPreview(params, { resolveParam })`** (текст рядом с действием в списке событий; `resolveParam(ключ)` форматирует поле как редактор: подпись варианта, «x: …, y: …», «w × h», имя анимации), **`meta.keywords`** (поиск действий; редактор нормализует запрос и ключевые слова: NFKD, без диакритики, разбиение camelCase, `&` → `and`, нижний регистр, затем всё, кроме `a-z0-9`, — в пробел, поэтому **кириллица в поиске не работает ни в запросе, ни в ключевых словах**; подтверждено пользователем в 1.2.1), `meta.category` (категория в результатах поиска; в списке действия плагина идут под его именем), `meta.disableInDialogueAction`.

**Что Toolkit использует с 0.8.0** (`src/editor/ui.ts`, отдельно от логики действий): разделы (Stats, Animations, Patrol, When, Then, When used, Look and size, Weapon layer, Placement, Interface, Debug) со свёрнутыми второстепенными, скрытие неприменимых полей, превью каждого действия, ключевые слова (только латиница, с 0.8.1), радиокнопки для коротких выборов, пределы чисел, обязательные поля, подписи кнопок выбора на карте, показ маршрута патруля и порядка переключателей на карте редактора.


## 13. Формат проекта, жизненный цикл карт и проверка в настоящем рантайме (2026-10-27)

По исходникам рантайма 1.2.1 (раздел 11), коду Electron-части редактора (раздел 12) и экспорту игры пользователя. Код PS Maker прочитан для совместимости и не копировался.

**Где лежат проекты** (`electron/main.cjs`: `getProjectsDataDir`): Linux — `$XDG_DATA_HOME` или `~/.local/share/PS Maker/projects/<папка>`, Windows — `%LOCALAPPDATA%\PS Maker\projects`, macOS — `~/Library/Application Support/PS Maker/projects`. Проект — папка с `story.json`, `assets/` (файлы по ключам ассетов) и `plugins/`; список проектов — просто подпапки. Запись сверяет `metadata.storyId`, поэтому у нового проекта свой id. `metadata.schemaVersion` 32 — последняя схема 1.2.1.

**Карта** (`Maps.ts`, `MapCollisions`, команды редактора):
- `terrainLayers[].terrainGrid[x][y]` = id террейна (ячейки по `tileSize`), автотайл «wang blob» по 8 соседям; первый слой («Details») рисуется над «Ground».
- `mapObjects[]`: `{ id, mapObjectId, position }`, позиция — **центр** картинки; коллизия — `collision.box` объекта из библиотеки.
- `mapCollisions[]`: `{ inGameId, x, y, width, height }` — прямоугольники от левого верхнего угла.
- `setupActions` («Map setup»: позиция игрока, NPC), `initialActions` («Map start», «When map first starts»), `enterActions` («Map enter», при каждом входе), `leaveActions`.
- Действие плагина в списке: `{ type: "plugin:<sanitizeName(плагин)>:<sanitizeName(действие)>", name, id, pluginName, actionName, pluginParams }`.
- Триггер «Add event trigger»: `triggerType` (`interact`, `touch`, …), `staticArea` и событие в `ownedStoryEvents` с `owner: { type: "action", actionId, relation: "local-trigger" }`.

**Области сохраняются по центру.** Редактор областей (`AreaEditor/areaGeometry.ts`) рисует прямоугольник от `x − width / 2`, а `TouchTrigger` — Phaser-прямоугольник с началом в центре. До 0.9.0 Toolkit считал `x/y` области `Create Wave Room` левым верхним углом: в настоящем редакторе арена сдвигалась на половину размера. Исправлено (`areaOf`), ширина/высота берутся по модулю (область, нарисованная «назад»).

**Возврат на карту.** Смена карты — `scene.switch` (`ActiveMap.switchMap`): уходящая карта **засыпает**, её состояние снимается (`MapStateTracker`), при возврате сцена **просыпается** и восстанавливается без повторного запуска «Map start» (`initialActions`); «Map setup» тоже не повторяется, «Map enter» выполняется при каждом входе. В 0.8.x Toolkit после возврата оставался привязан к другой карте — на поле не было ни врагов, ни объектов (воспроизведено в рантайме). С 0.9.0 Toolkit запоминает действия, построившие карту, и выполняет их снова по событию `wake` (`src/editor/mapReplay.ts`); на `sleep` сессия останавливается, прогресс сохраняется.

**Толкание блока.** Игрока двигает PS Maker (`body.setVelocity`), Toolkit выталкивает его из своих твёрдых объектов; в рантайме касание блока видно только в каждом 2–3-м кадре, и счётчик толчка сбрасывался. С 0.9.0 толчок переживает потерю касания до 150 мс, пока игрок стоит вплотную и смотрит на блок.

**Экспорт игры.** `game.dat` — BSON-версия `story.json`, ключи ассетов переписаны в `game-assets/<файл>`; плагины — `plugins/manifest.json` (`{ "plugins": ["….ps-maker.js"] }`) и файлы рядом. На этом основан `scripts/runtime-check.mjs`: демо-проект запускается в настоящем рантайме из экспорта пользователя (файлы рантайма в репозиторий не попадают).

**Проверено в рантайме PS Maker 1.2.1** (headless Chromium, экспорт пользователя, демо-проект из `scripts/make-demo-project.mjs`): загрузка плагина через manifest, все действия «Map start», внешний вид врагов из персонажей встроенного набора, сундук, переход «Change map» по триггеру касания, блок на плите, ключ и дверь, волны и страж, тайный сундук, возврат на поле с сохранением прогресса, без ошибок страницы.

## 14. Предпросмотр действий на карте редактора (2026-10-27)

Редактор показывает на карте только то, что создают его собственные действия: `editorPreviewPositions.ts` знает `spawnNPCAction`, `moveNpcAction`, `movePlayerAction` и т.п.; хука для плагинов нет. Поле «точка на карте» показывает жёлтый крестик только у выбранного действия (`showPreview`).

Что можно без изменения PS Maker: модуль плагина загружается в окно редактора, карта редактора — Phaser-сцена `GameMap` из `window.game`, у неё `inEditorMode === true` (в playtest и игре — нет) и данные карты в `scene.map` (их обновляет хранилище проекта при каждой правке). С 0.10.0 Toolkit (`src/editor/editorPreview.ts`) раз в 300 мс находит такую сцену и, если действия `Zelda:` изменились, перерисовывает поверх карты неинтерактивный слой: врагов (в облике выбранного персонажа — первый кадр стоя из текстуры `<animId>frames`, иначе встроенный спрайт) с подписью типа и группы, объекты, сундуки с содержимым, двери с размером и замком, предметы, точку возрождения, область комнаты с волнами, врагов волн и стража, маршруты патруля, порядок переключателей, связи «кнопка/плита → дверь». Карта проекта не меняется. Проверено на настоящей сцене рантайма 1.2.1 с `inEditorMode = true` (рантайм экспорта, не редактор); в самом редакторе — сценарий M-29.

**Выбор и коллизии (0.12.0).** Открыть настройки действия редактор умеет переходом по своему маршруту `/editor/<проект>/maps/<карта>/<id действия>?bc=root:<список>` (`openActionConfig`; список — `__map_setup__`, `__map_start__`, `__map_enter__`, `__map_leave__`), а строки списка событий помечены `data-action-id` (`revealAction`). Toolkit делает картинки предпросмотра кликабельными: щелчок выделяет картинку жёлтой рамкой и прокручивает список к её действию, двойной щелчок открывает настройки — ссылкой внутри приложения, как будто автор щёлкнул по ней (маршрутизатор SvelteKit перехватывает её без перезагрузки; если не перехватит, щелчок отменяется). Открытое из списка действие тоже выделяется на карте. Переключатель коллизий редактора внутренний; его состояние видно по собственным прямоугольникам коллизий карты (`scene.collisions[].visible`, иначе `collisionBoxVisual` объектов), и коллизии Toolkit (тела врагов по их размеру или коробке персонажа, твёрдые объекты, сундуки, закрытые двери) показываются и прячутся вместе с ними. Проверено на сцене рантайма 1.2.1 с `inEditorMode = true`: выделение, адрес перехода, коллизии; сам переход — только в редакторе (M-29).

## 15. Твёрдые объекты в физике PS Maker (0.14.0)

Игрока двигает PS Maker (`body.setVelocity` в `Player.update`, шаг Arcade на каждом кадре), а Toolkit работает фиксированными тактами 60 Гц в `postupdate`. Пока твёрдые объекты Toolkit не были телами физики, движок каждый кадр заводил игрока в блок, а Toolkit выталкивал его только на своих тактах; на кадрах без такта (экран быстрее 60 Гц) игрок рисовался внутри блока — камера, следящая за ним, дрожала (воспроизведено: при 15 тактах на ~35 кадров x 75↔79). С 0.14.0 `PhaserHost.syncSolids` держит пул `Zone` со статическими телами в `physics.add.staticGroup()` и один `physics.add.collider(player, group)`; пул обновляется, только когда меняется набор твёрдых объектов (сдвинулся блок, открылась дверь, подняли горшок). Свои зоны помечены `zmtSolid` и не попадают в кеш стен для врагов. «Упёрся» = `player.body.touching[направление взгляда]` и твёрдый объект в 2 px перед игроком.

## 16. Объекты карты как облик объектов Toolkit (0.16.0)

- Типа параметра плагина «объект карты» в PS Maker 1.2.1 нет (есть `npc`, `image`, `sound`, переменные и т.п.), поэтому поле — `string-enum` с выпадающим списком. `PluginRegistry` хранит описания действий по ссылке, а форма читает `options` при открытии, поэтому Toolkit дописывает в общий массив вариантов объекты открытого проекта (`fillMapObjectOptions`, из `scene.map`-сцены редактора, раз в 300 мс); в сохранённом действии лежит id объекта.
- Библиотека — `story.mapObjects[]`: `{ id, name, type: "static" | "animated", collision: { enabled, box: { x, y, width, height } }, animationConfig }`; коробка задана от левого верхнего угла картинки. `LoadingScene` грузит все объекты библиотеки текстурой под их id (анимированные — листом `<id>_frames`), независимо от того, стоят ли они на карте.
- Экспорт: отсечение неиспользуемых ассетов не работает, если в проекте есть плагины, и сканирует все строки проекта, включая `pluginParams`, поэтому выбранные объекты попадают в экспорт.
- Проверено в рантайме экспорта 1.2.1 (проект-заготовка с *Small Bush*, *Short Stump*, *Crate* из встроенного набора): облик виден, тело по коробке, пень остаётся после удара мечом, сундук-ящик открывается. В редакторе подтверждено пользователем: список заполняется, выбранные объекты видны на карте; в игре пень остаётся, сундук открывается (M-30).

## 17. Интерфейс PS Maker 1.2.1: меню, диалоги, сохранения (0.17.0)

Источник — исходный код рантайма (экспорт игры) и сборка редактора.

**Главное меню.** Титульного экрана нет: игра начинается с `player.startingMap` (`LoadingScene`). Действие **Add UI** (`addUiComponentsAction`: `uiName`, `inGameUiId`, `fadeEnabled`, `fadeDurationMs`, `waitForCompletion`, `components`) кладёт поверх карты компоненты `text`, `image`, `rectangle`, `button` (`componentId`, `position` — центр в логических пикселях игры `gameConfig.width × height`, `size`, `sizeAnchor`, `zIndex`). Кнопка (`styleId` из `gameUI.buttonStyles`, `label`, `storyEventId`) запускает событие проекта (`InGameUiOverlay.runButtonEvent` → `findScopedStoryEvent`). Редактор сохраняет событие кнопки скрытым и принадлежащим ей: `owner: { type: "action", actionId, actionType: "addUiComponentsAction", relation: "button-click", componentId }` (`storyEventOwnership.ts`). Пока открыт диалог или выбор, кнопки неактивны. Для меню есть действия **Open load game menu** (`openLoadGameMenuAction`), **Open game options menu** (`openOptionsMenuAction`: `showExitGameButton`, `showSaveGameButton`), **Exit game** (`exitGameAction`), а игрока прячут **Set player visibility** (`mode: "hide"`) и **Toggle player movement** (`mode: "disable"`).

**Меню опций и загрузки** (`systemMenus`): открываются с `pauseGame()` → `window.game.pause()` и `sound.pauseAll()`, закрываются с `resumeGame()`. Toolkit работает в `postupdate` сцены и при паузе стоит. Phaser при `game.pause()` / `resume()` шлёт `pause` / `resume` в `game.events`: по ним Toolkit отбрасывает нажатия, сделанные в меню (по `KeyboardEvent.timeStamp`). Ползунок громкости звуков меняет `game.audioSettings.soundVolumePercent`; свои звуки PS Maker умножает на него через `audioSettings.scaleSoundVolume(volume)`, и Toolkit делает так же (`PhaserHost.playSound`). Стили — `gameUI.optionsMenu`, `gameUI.loadGameMenu`.

**Диалоги** (`Dialogue`: `dialogueSource` с командами `@name`, `@portrait`, `@dialogue_layout`, `@dialogue_speed`…; пустая строка — новая страница). Вид — `gameUI.dialogLayouts[]` (`textBox: { width, height, padding, background, textStyles }`, `nameBox`, `portrait`, `bottomGap`, `typingSpeed`, `caret`) и `defaultDialogLayoutId`. Фон UI: `{ type: "plain", backgroundColor, backgroundOpacity, borderColor, borderWidth, borderRadius }` или `{ type: "image", imageId, backgroundOpacity, scalingMode: "nine-slice" | "fit" | "fill" | "tile" | "stretch", borderWidth, slice: { top, right, bottom, left }, repeat }` (`background.ts`; варианты масштаба — из формы редактора). 9-slice (`NineSliceBackground.svelte`) рисует углы картинки размером `slice` в квадраты `borderWidth` (уменьшая, если окно меньше двух бордюров), стороны и середину растягивает. API для показа диалога PS Maker из плагина нет, поэтому окно сообщений Toolkit рисует сам Toolkit по тому же макету.

**Шрифты** (`fontAssets.ts`): шрифт проекта (`gameUI.fonts[]: { id, name, key }`) регистрируется как `FontFace("ps-maker-font-<id>")` при первом показе текста, который его использует (диалог, меню, текст Add UI), а не при запуске игры. Toolkit пишет семейство как `"ps-maker-font-<id>", "<name>", <запасной>` и перерисовывает текст по `document.fonts` `loadingdone`.

**Картинки** (`story.images[]: { id, name, url }`, `url` — ключ файла в `assets/`, в экспорте — `game-assets/<ключ>`) загружаются `LoadingScene` текстурами Phaser под `id`. Ими пользуются `Zelda: HUD Style` и фон окна сообщений.

**Сохранения** (`saveLoad`): `collectSaveState` сохраняет позицию игрока, все переменные (`game.variables.variables`), музыку, снимки карт (`MapStateTracker`) и незавершённые выполнения событий. `loadGame` пересоздаёт игру (`createGame`), карты строятся из снимков, затем `restoreGlobalState` записывает переменные. Карта со снимком **не** выполняет «Map setup» и «Map start» заново: `MapStartup` продолжает только сохранённые незавершённые выполнения (`needsStart = !hasSnapshot || savedSetup.length > 0`). Значит, после загрузки `Start Toolkit` не выполняется. Toolkit с 0.17.0 следит за сценами (`src/editor/saveRestore.ts`): у сцены карты есть поля `mapStartSnapshot` и `hasSavedMapStartup`; если снимок есть, а сохранённого запуска нет, Toolkit выполняет действия `Zelda:`, строящие карту, из `map.setupActions` и `map.initialActions` сам. Прогресс Toolkit хранится в текстовой переменной проекта (`Start Toolkit` → *Progress variable*): PS Maker сохраняет и восстанавливает её вместе с остальными.

Проверено в рантайме экспорта 1.2.1 (`scripts/runtime-check.mjs`, демо 0.17.0): титульная карта с кнопками; «New game» переносит на поле; Escape открывает меню опций и Toolkit стоит; «Save game»; перезагрузка страницы; «Continue» → меню загрузки → сохранение: Toolkit запускается на восстановленной карте, открытый сундук открыт. Диалог PS Maker с фоном-картинкой и окно Toolkit по тому же макету. В редакторе — сценарии M-31…M-33 в TESTING.md.

## 18. Add UI с переменными, Dialogue из плагина, адреса файлов (0.18.0)

- **Привязки Add UI** (`resolveUiComponent.ts`, `variableValue.ts`). Значение свойства — `UiPropertyValue`: константа, `{ type: "variable", variableId }` или `{ type: "expression", source }`. Привязываются: позиция X/Y, ширина и высота, поворот, z-index, прозрачность, текст (`label`), прозрачность фона (`background.backgroundOpacity`). Картинка компонента (`imageId`) постоянна. Выражения: `@{id переменной}`, числа, строки, `true`/`false`, `+ − * /`, скобки — без сравнений и округления. При изменении переменной (`game.variables.set` → `gameVariablesRevision`) UI пересчитывается. Фон-картинка с масштабом *Tile* повторяется в натуральном размере (`background-repeat: repeat; background-size: auto`) в логических пикселях UI. Привязка размера `sizeAnchor: "top-left"` — позиция задаёт левый верхний угол, ширина растёт вправо (`sizeAnchor.ts`).
- **Dialogue из плагина.** У сцены карты публичный `storyRunner` (по нему же `collectSaveState` находит карты); `storyRunner.playActions(actions)` выполняет список действий как событие карты и возвращает промис, который выполняется по завершении. Toolkit передаёт `{ type: "dialogueAction", dialogueSource }` (`Dialogue.ts`). Синтаксис источника (`dialogueSourceParser.ts`): строка «Имя: текст» задаёт говорящего, строка с `@` — команду, `\` в начале строки отменяет и то и другое, `\` перед `*`, `_`, `{`, `}` — разметку. `@dialogue_layout <id>` выбирает макет по id (`resolveLayout`).
- **Адрес файла ассета** (`fontAssets.ts resolveFontUrl`, `asset.ts fetchAssetUrl`, electron `main.cjs`). В экспорте ключ уже имеет вид `game-assets/<файл>` (`packagedAssetUrl` кодирует каждый сегмент). В настольном редакторе адрес даёт `window.psMakerDesktop.storage.getAssetUrl(папка проекта, ключ)` → `<протокол>://file/<encodeURIComponent(полный путь)>`; папка — сегмент маршрута редактора `/editor/<папка>/`. Phaser грузит картинки как `blob:`, поэтому вычислить адрес по текстуре нельзя.
- **Запуск карты после загрузки:** `MapStartup.needsStart = !hasSnapshot || savedSetup.length > 0` (поле экземпляра `scene.mapStartup`) — Toolkit сам выполняет действия карты, только если PS Maker «Map start» не выполнит.

Проверено в рантайме экспорта 1.2.1 (`scripts/runtime-check.mjs`): HUD на Add UI меняет ширину ряда сердец и число рупий по переменным; табличка показана диалогом PS Maker с текстом как написан; Toolkit загружает шрифт из `game-assets/`. Настольный редактор — по исходному коду (`preload.cjs`, `main.cjs`), не запускался: сценарий M-35 в TESTING.md.

## 19. Камера игры, карта редактора, формы действий, шрифты (0.19.0)

- **Камера в игре** (`initCamera`): `camera.setZoom(CAMERA_ZOOM)`, `camera.startFollow(player)` без границ — камера держит игрока в центре и показывает и то, что за краем карты. Поэтому рамка «Game window» в редакторе — размер окна игры (`gameConfig.width / height`), делённый на `CAMERA_ZOOM`, с центром в точке старта игрока (`movePlayerAction` с `absolute-position` в «Map setup»).
- **Карта в редакторе** (`enterMapEditorMode` / `exitMapEditorMode`): та же сцена карты с `inEditorMode = true`; камеру двигает и масштабирует редактор, следование за игроком выключено. Объекты, добавленные плагином на сцену (графика, картинки, зоны с `setInteractive({ draggable: true })`), получают события мыши Phaser поверх карты; инструменты редактора (выделение) по ним не срабатывают — данные карты, кроме полей HUD Style, после перетаскивания не изменились.
- **Формы действий** — обычные поля `<input>` в панели `[data-map-editor-action-config-panel="true"]`; последний пункт её навигации (`nav[aria-label="Breadcrumb"]`) — имя действия, подпись поля — элемент `.label` в строке поля. Значение, записанное через нативный сеттер `HTMLInputElement.value` с событиями `input` и `change`, редактор принимает как ввод: оно попадает в данные карты (`scene.map`, `pluginParams` действия) и сохраняется в `story.json` проекта. Свёрнутые разделы формы — `<details>`.
- **Шрифты** (`fontAssets.ts`): шрифт проекта — файл TTF из `gameUI.fonts[]`, без подмены глифов. В PixelOperator (шрифт нового проекта) кириллицы нет, и браузер рисует русские буквы другим шрифтом из списка (по умолчанию — с засечками). Нужен шрифт с кириллицей в макете диалога и стилях текста.

Проверено: сборка редактора PS Maker 1.2.1 (renderer из приложения, без Electron) запущена в Chromium с веб-хранилищем проекта (OPFS вместо файлов, стили интерфейса загрузились не все). На карте Field демо видна рамка Game window с HUD Toolkit в пикселях карты; перетаскивание сердец мышью записало *Hearts X/Y* в форму, в `scene.map` и в `story.json` хранилища; остальные данные карты не изменились. Настольное приложение (Electron) с этим не запускалось. Шрифты — в рантайме экспорта 1.2.1 (`scripts/runtime-check.mjs`): ширина «ЖыщЮя» в PixelOperator совпадает с шириной запасного шрифта (глифов нет), в Pixelify Sans — отличается.
