## [0.9.1] — 2026-10-27

- Демо-проект: ящики в подземелье загораживали подход к двери с ключом (сообщил пользователь). Ящики перенесены в угол комнаты; тест проверяет, что декор не стоит ближе 40 px к дверям и 28 px к сундукам, головоломкам, старту и NPC; `runtime-check.mjs` теперь идёт к двери пешком из середины комнаты, а не телепортируется к ней (со старой расстановкой проверка падает).

## [0.9.0] — 2026-10-27

Проверено в настоящем рантайме PS Maker 1.2.1 (веб-экспорт пользователя): найдены и исправлены три ошибки, которых не было видно в эмуляторе (ENGINE_AUDIT, раздел 13).

### Добавлено
- **Демо-проект PS Maker одной командой:** `node scripts/make-demo-project.mjs --from "<проект>"` создаёт рядом проект «Zelda Toolkit Demo» — поле и подземелье на встроенном наборе «Tiles 'N Such Assets» (террейн, объекты, коллизии, стражник, переходы между картами, облик врагов из персонажей набора: Slime, Bone Slime, Magma Slime, New Male, Bull). Исходный проект только читается, существующая папка не перезаписывается.
- `scripts/runtime-check.mjs` — прохождение демо в настоящем рантайме PS Maker из вашего веб-экспорта (8 проверок; файлы экспорта в репозиторий не попадают).

### Исправлено
- **Возврат на карту.** PS Maker при смене карты усыпляет сцену, а при возврате будит её, не запуская «Map start» заново. Toolkit оставался на прошлой карте — на поле после подземелья не было врагов и объектов. Теперь Toolkit запоминает действия, построившие карту, и выполняет их снова, когда карта просыпается; эффекты (выдать предмет, сообщение, сохранение) не повторяются, прогресс сохраняется.
- **Толкание блоков в PS Maker.** Касание блока было видно лишь в каждом 2–3-м кадре, и счётчик толчка сбрасывался — блок не двигался. Толчок теперь переживает потерю касания до 150 мс, пока игрок стоит вплотную и смотрит на блок.
- **Область `Create Wave Room`** читается от центра, как её сохраняет редактор PS Maker (раньше арена сдвигалась на половину размера); область, нарисованная «назад», тоже работает.

### Изменено
- Демо-карты выровнены по сетке 16 px; двери подземелья — в два тайла (у игрока PS Maker нет «соскальзывания» с углов).
- Эмулятор хоста в интеграционном тесте ведёт себя как PS Maker: сцена на каждую карту, смена карты через `scene.switch`, «Map start» один раз.

## [0.8.1] — 2026-10-27

### Исправлено
- Поиск действий по русским словам не работал (проверено пользователем в PS Maker 1.2.1). Причина — в редакторе: перед сравнением он переводит запрос и ключевые слова в нижний регистр и заменяет все символы, кроме латиницы и цифр, пробелами, поэтому «враг» превращается в пустую строку (ENGINE_AUDIT, раздел 12). Из плагина это не исправить; русские ключевые слова удалены, английские дополнены синонимами («foe», «slime», «loot», «lock», «rupee»…). Тест проверяет, что ни одно ключевое слово не стирается поиском редактора.

## [0.8.0] — 2026-10-27

По коду редактора PS Maker 1.2.1 (см. `docs/ENGINE_AUDIT.md`, раздел 12): редактор рисует поля плагинов теми же компонентами, что и встроенные, и читает ещё ряд свойств. Теперь Toolkit ими пользуется (`src/editor/ui.ts`; поведение действий не менялось).

### Добавлено
- **Разделы** в формах, второстепенные свёрнуты: у `Create Enemy` — Stats, Patrol, Animations; у `Create Object` — When used, Look and size; у правил — When / Then; у `Start Toolkit` — Interface, Game, Debug; у `Set Player Sprites` — Weapon layer, Placement.
- **Поля показываются, только когда нужны**: *Count* — только для считаемых предметов (рупии, бомбы, стрелы…); *Spawn at* — когда выбран враг; второй объект условия — когда выбран первый; *Stays on* — у плит, рычагов, кнопок; *Reacts to* — у глаза, кнопки, разрушаемых, факела; *Text* — у таблички и переключателей; «When used» — у объектов, которые активируются; у `Damage Target` группа и объект скрыты при «Hit the player»; у `Define Item` настройки атаки скрыты для лечебного предмета; настройки HUD скрыты, если HUD выключен.
- **Превью в списке событий**: «Create Enemy: Ogre, Group 2, x: 10, y: 20», «Add Rule: Group 1 defeated → open door, give 20 Rupees», «Give Item: 5 Bombs» и т.д.
- **Поиск действий** по ключевым словам («enemy», «chest», «door», «shop»…). Русские слова поиском редактора не находятся — см. 0.8.1.
- **Радиокнопки** для сложности, языка, замка двери, ячейки сохранения; **пределы и шаг** для чисел (сердца 1–20, громкость 0–1 с шагом 0,1, время с шагом 100 мс…); **обязательные поля** подсвечиваются (точка объекта, область комнаты, порядок переключателей…); подписи кнопок выбора («Pick door», «Draw route»…).
- Маршрут патруля и порядок переключателей **видны на карте редактора**.

## [0.7.1] — 2026-10-26

### Исправлено
- Враг при атаке проходил сквозь игрока: выпад продолжался после касания, а пока игрок мигал, враг шёл насквозь, и отбрасывание могло направить игрока не в ту сторону. Теперь касание — «толчок», как в A Link to the Past: враг прерывает выпад и отскакивает назад (`enemies.contactRecoil`, по умолчанию 140 пикс./с), игрок отлетает от врага; пока игрок неуязвим, враг выталкивается из него.

## [0.6.0] — 2026-10-25

По исходному коду рантайма PS Maker 1.2.1 из экспорта игры (source maps), см. `docs/ENGINE_AUDIT.md`, раздел 11.

### Исправлено — главная причина «враг не появляется»
- PS Maker выполняет действия события по очереди и **ждёт `ctx.endAction()`** от каждого. Действия Toolkit его не вызывали, поэтому событие останавливалось на `Start Toolkit`, а `Create Enemy` и всё после него не выполнялось. Теперь каждое действие завершает себя (и при ошибке). Опубликованные типы `@ps-maker/plugin-api@0.0.3` этого требования не описывают.

### Изменено: штатные виджеты PS Maker
- *Position* — тип `map-position`: кнопка выбора точки на карте, как у встроенных событий.
- Выпадающие списки (`string-enum`): сложность, язык, шаблон врага (+ поле *Custom template* для своих), тип объекта, замок двери (вместо трёх галочек), операция `Change Object`, тип урона, момент звука, ресурс предмета.
- `Enemy From NPC` — список NPC на карте (`in-map-npc`).
- `Set Player Sprites` — выбор анимации игрока из PS Maker (`player-animation-picker`) для атаки и урона вместо галочки 0.5.2.
- Сохранённые старыми версиями значения (числовая сложность, галочки замка, галочка 0.5.2) продолжают работать.

### Добавлено
- Бой сам встаёт на паузу, пока на экране диалог PS Maker (`GameMap.playingDialogue`); `combat.pauseDuringDialogue`.
- Анимации из PS Maker берутся из его собственных текстур (`<id анимации>frames`), номера кадров — по ширине картинки, как в PS Maker.
- Поиск NPC по `inGameCharacterId`.

### Удалено
- Запуск действий из данных карты (0.5.3) — обход больше не нужен.
- Плагин-зонд `tools/param-probe` — вопрос о типах полей решён по исходному коду.

## [0.5.3] — 2026-10-25

По скриншоту playtest 0.5.2: данные проекта найдены (`scene.data.story`), но PS Maker снова вызвал только `Start Toolkit` (×5), а `Create Enemy` — ни разу, без ошибок.

Действия `Zelda:`, сохранённые сразу после `Start Toolkit` в том же списке (до первого действия другого типа — ожидания, диалога и т.п.), которые PS Maker не вызвал за 0,5 с, Toolkit выполняет сам. В панели: предупреждение `PS Maker did not call … ran from the map data`, в `actions run:` — пометка `(map data)`. Если PS Maker всё-таки вызовет такое действие позже, повторный вызов пропускается.
- Строка диагностики `map events (saved): …` — какие действия сохранены в событиях карты.

## [0.5.1] — 2026-10-25

По файлу проекта PS Maker 1.2.1 (story.json), см. `docs/ENGINE_AUDIT.md`, раздел 10.

### Исправлено
- PS Maker не сохраняет нетронутое поле *Position* (в проекте у `Create Enemy` не было ключа `position`). Теперь враг или объект без Position ставится рядом с игроком, а в диагностике — предупреждение; раньше действие ничего не создавало.

### Добавлено (экспериментально)
- `Create Enemy` → **PS Maker character**: анимации персонажа из библиотеки PS Maker (листы `… Run/Walk`, `Idle`, `Attack`, `Hurt`, `Death`), порядок направлений и коллизия.
- `Set Player Sprites` → **Attack sheet (PS Maker)**, **Hurt sheet (PS Maker)**: листы игрока по названию (например, `Sword Attack`).
- Toolkit ищет данные проекта во время игры и показывает результат строкой `PS Maker data:` в диагностике. Где именно PS Maker хранит их в игре, не подтверждено.
- В диагностику попадают и `console.warn` страницы (не только ошибки).

### Тесты
- Имена действий закреплены тестом: PS Maker сохраняет действие под ключом из имени (`plugin:zelda-maker-toolkit:zelda-create-enemy`), переименование потеряло бы его в проектах.
- Интеграционная проверка «ключ из сундука» ждёт результат опросом вместо фиксированной паузы (под нагрузкой сундук открывался на несколько кадров позже).

## [0.5.0] — 2026-10-25

### Изменено: формы без JSON
Все поля, где нужно было писать JSON, заменены обычными полями: галочками, числами, короткими списками через запятую. Выпадающих списков и кнопок API плагинов PS Maker (0.0.3) не даёт — выбор из вариантов сделан галочками и числами.

| Действие | Было | Стало |
|---|---|---|
| `Start Toolkit` | Preset (текст), Config JSON | Difficulty (1–3), Hearts, Sword damage, Show HUD, Magic bar, Shield on a button, HUD at the bottom, Autosave, Positions in tiles |
| `Configure` | Config JSON | заменено на `Zelda: Set Controls` — клавиши по полям (`X`, `Space`, `Shift`, `Tab`, `Up`…) |
| `Create Enemy`, `Enemy From NPC`, `Add Wave Enemy` | Overrides JSON, Animations `walk=…` | Health, Damage, Speed (0 = как в шаблоне), Walk/Attack/Hurt/Death animation, Sprite offset X/Y, Sprite scale |
| `Create Object` | Config JSON | Hidden, Stays on, Width, Height, Text, Reacts to, On use: set flag / open doors / reveal |
| `Create Door` | Lock (текст) | галочки Needs a small key, Needs the Big Key, Opened by switch; Width, Height |
| `Add Rule`, `Run Actions` | When/Then/Else JSON | When group defeated, When objects active, When flag set, When player has, When boss defeated → Open doors, Reveal, Set flag, Give item + count, Message, Spawn enemy + marker |
| `Create Switch Sequence`, `Create Wave Room` | On solved / On cleared / Advanced JSON | те же поля действий; у комнаты — Pause between waves (ms) |
| `Change Player Stats` | Stat, Mode (текст) | Health, Max health, Magic + галочка Set instead of add |
| `Define Item` | Item JSON | Item ID, Name, Icon, Uses, Cost, Damage, Damage type, Area attack, Stun, Heal |
| `Define Enemy` | Template JSON | Based on, Health, Damage, Speed, Sight range, Boss, Immune to, Sprite offset/scale |
| `Define Animation` | Frames JSON по направлениям | Frames (facing down), Frames facing up / left / right |
| `Set Player Sprites` | Weapon behind in (текст) | четыре галочки направлений; Swing center X/Y |

**Совместимость.** Действия, сохранённые старыми версиями, продолжают работать: старые JSON-поля применяются с предупреждением «re-open the action», а новые поля, которых у старого действия нет, ничего не сбрасывают. Полный словарь правил и все настройки остаются в JS API (`ZeldaMakerToolkit.addRule`, `runActions` — новые, `configure`, `registerEnemyTemplate`, `defineItem`).

### Добавлено
- Названия клавиш без учёта регистра: `shift`, `tab`, `esc`, `up`/`down`/`left`/`right`.
