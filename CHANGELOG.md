## [0.24.0] — 2026-10-30

Просил пользователь: исправить то, что при настройке интерфейса щелчки задевают карту, и добавить возможности, которые видны на картинках страницы Hendrix HUD Designer (идеи; код и данные того плагина не использовались).

### Исправлено
- **Щелчки дизайнера больше не доходят до карты.** Мышь над рамкой *Game window* берёт элемент страницы с отметками, которыми редактор PS Maker помечает свои элементы управления поверх карты: левые и правые щелчки получает только дизайнер, а колесо и средняя кнопка по-прежнему прокручивают и масштабируют карту (ENGINE_AUDIT, раздел 22). Выделение и ручки рисуются этим же слоем.

### Добавлено
- Дизайнер как графический редактор: меню по правому щелчку (создать элемент там, где щёлкнули; копировать, вырезать, вставить, дублировать; порядок; группировать; заблокировать; выровнять и распределить); выделение нескольких (Shift+щелчок, рамка); прилипание к краям и центру окна и к краям других элементов с направляющими, сетка 2–16 пикселей; восемь ручек размера (Shift — пропорции); поворот за ручку (Shift — по 15°); клавиши Ctrl+C / X / V / D / A / G, Ctrl+[ ]. Смена якоря оставляет элемент на месте.
- Свойства всех элементов: прозрачность, эффект (мигание, пульсация, покачивание, дрожание), поворот (картинки, тексты, иконки), группа, блокировка; условие показа «значение сравнивается с числом».
- Полосы-фигуры без картинок: прямоугольник, пилюля, круг, ромб, треугольник, звезда, сердце; цвет и толщина рамки; подпись поверх. Обводка текста.
- Новые элементы: **Icon** (иконка из листа, выбор щелчком по листу), **Quick slot** (слоты быстрого доступа: N-й предмет; клавиши 1–9 берут его в руку, `controls.hotbar`), **Minimap** (стены карты, враги, объекты вокруг игрока; круг или прямоугольник).
- Экраны: звуки (открытие, закрытие, перемещение выбора, нажатие); экран без клавиш — слой над HUD, под которым игра идёт (полоса босса, надпись); `Close UI Screen` закрывает экран или слой по имени.
- Каждый элемент рисуется на своей глубине: фигура или текст, поставленные выше картинки в списке, рисуются поверх неё.
- Демо: мигающая надпись «LOW HEALTH», пока у игрока осталось одно сердце.

## [0.23.0] — 2026-10-29

Просил пользователь: дизайн UI «примерно как в плагине Hendrix HUD Designer», в редакторе, с заменой `HUD Style`. Идея взята, код и данные того плагина не использовались. Действий 38 (было 36).

### Добавлено
- **`Zelda: UI Layout` — дизайнер HUD и экранов на карте редактора.** Пока действие открыто, слева панель, а HUD в рамке *Game window* редактируется мышью: выбрать, перетащить, потянуть за угол; стрелки (Shift — на 8), Delete, Ctrl+Z / Ctrl+Y; добавить элемент, порядок рисования, шаблон *Classic HUD*. Элементы: картинка (растянуть, 9-slice, вписать), текст со значениями (`{rupees}`, `{var:<id>}`, `{t:hud.life}`), полоса, сердца, счётчик с лентой цифр, рамка предмета, кнопка. У каждого — якорь (угол или край окна игры), условие показа (переменная, предмет, без диалога). Тема макета: масштаб, шрифт и цвет текста, панель и курсор инвентаря, иконки встроенных предметов. Макет хранится в поле *Layout data* (версия формата 1, все поля проверяются при чтении); дизайнер пишет его так же, как ввод, и PS Maker сохраняет его с картой. Щелчок по HUD в рамке открывает действие.
- **Экраны меню.** `UI Layout` с *Screen name* — экран поверх игры (пауза, магазин…): затемнение, пауза игры и игрока, открытие клавишей Menu (Enter, `Set Controls` → *Menu*, геймпад 8). Действия **`Zelda: Open UI Screen`** и **`Zelda: Close UI Screen`**. Кнопки выбираются стрелками (крестовина 12–15) и мышью, нажимаются Z или щелчком; X, I или Menu — назад; экран, открытый с другого, возвращается к нему. Кнопка запускает событие PS Maker (через его действие «Run event»), открывает или закрывает экран, меняет переменную. События `zelda:ui:screen`, `zelda:ui:button`.
- HUD, показывающий переменные проекта, перерисовывается несколько раз в секунду (PS Maker меняет переменные без событий Toolkit).
- Демо: HUD собран в `UI Layout` (две панели 9-slice); экран паузы по Enter с кнопками *Continue*, *Settings* (меню опций PS Maker с сохранением) и *Main menu* (на титульную карту) через глобальные события проекта; на табличке — «Enter: pause».

### Изменено
- Классический HUD — тоже макет (`classicLayout`); один код рисования (`LayoutPainter`) для игры и для рамки в редакторе.
- Раздел `ui` конфигурации: остались `enabled, showMagic, position, scale, messageMs, inventoryPanel, pauseWhileInventoryOpen`.

### Удалено
- **`Zelda: HUD Style`** и его поля (слоты картинок, части, позиции X/Y, шрифт). В старых проектах PS Maker пропускает это действие с предупреждением в консоли; HUD становится классическим, пока не добавлен `UI Layout` (см. docs/UI.md, «Переход с HUD Style»).
- Опции `ui.showHearts`, `showActiveItem`, `counters`, `safeArea`, `fontFamily`, `skin`, `barSlice`, `panelSlice`, `showLifeLabel`, `textColor`, `places`; выпадающий список шрифтов действий (шрифты выбираются в дизайнере).

## [0.22.0] — 2026-10-29

Просил пользователь: убрать функции, которые дублируют PS Maker, и привести демо в порядок. Действий стало 36 вместо 40.

### Удалено
- **Окно сообщений Toolkit** (`Message Style` → *Toolkit box*): сообщения Toolkit показывает только диалог PS Maker. У `Message Style` остались поля *Dialogue layout* и *Messages as dialogues*; поля *Show with*, *Type letter by letter*, *Wait for the action key*, *Pause the game*, *Position* убраны (игра ждёт, пока открыт диалог, всегда). Если движок не может показать диалог, сообщение становится заметкой HUD.
- **`Zelda: HUD Variables`**: значения Toolkit в переменные кладёт `Zelda: Show Stat In Variable` (у него все те же значения).
- **Сохранения Toolkit**: действия `Save Progress`, `Load Progress`, `Reset Progress`, сохранение в `localStorage`, автосохранение, поле *Autosave* у `Start Toolkit`, раздел `save` конфигурации, правило `save`, функции `save`/`load` JS API. Прогресс Toolkit сохраняет только PS Maker — через переменную прогресса (`Start Toolkit` → *Progress variable*).
- **Крюк** (был экспериментальным и выключенным): предмет, его настройки, анимация в `Set Player Sprites`, иконка в `HUD Style`, тип урона `hookshot`, объект `hook_post`.

### Изменено
- Демо: табличка у старта — две страницы без служебной клавиши F9, с подсказкой «Esc: menu and save»; описание прохождения и клавиш обновлено.
- Текст HUD в шрифте проекта рисуется как задуман шрифтом (без искусственного жирного); жирный — только у запасного моноширинного.
- Эмулятор хоста в тестах показывает диалоги как PS Maker (`storyRunner.playActions`); клавиши F5/F8/F6 из него убраны.

## [0.21.0] — 2026-10-28

Ревизия по исходнику редактора PS Maker 1.2.1 (просил пользователь: «проверь всё ещё раз, удали ненужные куски кода, облегчи»). Около 500 строк кода меньше; поведение в проектах пользователя то же. Подробности — ENGINE_AUDIT, раздел 20.

### Изменено
- Значения полей читаются в том виде, в каком их сохраняет PS Maker: точка `{ x, y }`, персонаж — id в библиотеке, картинка и звук — id ассета, NPC на карте — `inGameCharacterId` в `scene.NPCs`. Перебор «любых возможных форм» убран.
- Данные проекта — `scene.story` карты, id карты — `scene.map.id`, лист анимаций — текстура `<id анимации>frames`. Обход объектов игры в поисках проекта и поиск листа по имени файла или URL убраны.
- Эмулятор хоста в интеграционных тестах устроен как движок: `scene.map`, `scene.NPCs` с `inGameCharacterId`.

### Удалено
- Поддержка полей действий, сохранённых версиями 0.4–0.9, которых нет в проектах пользователя: JSON-поля (`when`, `then`, `else`, `overrides`, `config`, `json`), `preset`, `stat`/`mode`/`amount`, флажки замков дверей, id объектов текстом, списки через запятую. `mapId`, числовая сложность и `id` у Create Enemy (они есть в проекте «Istina») читаются как раньше.
- Проверка столкновений со слоями тайлов (`world.useTilemapLayers`): PS Maker не включает столкновения у тайлов, коллизии карты — статические тела.
- Неиспользуемые функции и константы (`distSq`, `approach`, `oppositeFacing`, `validateAnim`, `playerSheetAnim`, `playerAutoAnims`, `findStory`, `findCharacter`, `pickImageSource`, `parseJsonObject` и др.).
- Пометка «experimental» у поля *Look* в Create Enemy: облик персонажа проверен в рантайме.

## [0.19.0] — 2026-10-28

Просил пользователь: «HUD рисовался как карта в Game Window» — и пиксели HUD как у карты, и HUD виден в окне игры на карте редактора и двигается мышью. Сообщил: «шрифт всё равно остался неправильный» (окно таблички и сундука).

### Добавлено
- **HUD на карте в редакторе:** жёлтая рамка *Game window* (экран игры в начале: окно игры ÷ масштаб карты, центр — старт игрока) и HUD Toolkit в ней, нарисованный тем же кодом, что в игре. Части HUD (сердца, счётчики, рамка предмета, шкала магии) перетаскиваются мышью; при отпускании Toolkit вписывает их положение в форму `Zelda: HUD Style`, и PS Maker сохраняет его с проектом.
- `Zelda: HUD Style` → *Positions*: **Hearts / Counters / Item box / Magic meter X, Y** (−1 — классическое место). У сдвинутых частей свой фон из *Bar background* вместо общей полосы.
- **Scale 0 — «как карта»:** один пиксель картинки HUD равен пикселю карты (при масштабе карты 4 — 4 пикселя экрана). Это значение по умолчанию.

### Исправлено
- **Шрифт в окне таблички и сундука.** Причина — в PixelOperator (шрифт нового проекта PS Maker) нет кириллицы: «Получено: Бумеранг!» и «- ЖИЗНЬ -» браузер рисовал другим шрифтом. В демо теперь шрифт Pixelify Sans с кириллицей (SIL OFL 1.1, `scripts/demo-assets/`) — в макете диалога, кнопках, меню, текстах титульной карты и HUD. В docs/UI.md — как выбрать шрифт с кириллицей в своём проекте.

### Изменено
- Демо упрощено: HUD рисует Toolkit целиком (все части, Scale 0); HUD на Add UI, `Zelda: HUD Variables`, переменные «HUD …» и картинки `…-4x` из демо убраны. Сами `HUD Variables` и `Show Stat In Variable` остались для тех, кто собирает HUD на Add UI.
- `scripts/runtime-check.mjs` запускает игру с русским языком браузера, как у пользователя, и проверяет шрифт с кириллицей в окне сундука.

## [0.18.0] — 2026-10-28

### Добавлено
- **HUD на Add UI** (просил пользователь: «настроить HUD так же, как через Add UI»): `Zelda: HUD Variables` держит в переменных проекта целые сердца, половинку (1/0), контейнеры сердец, магию в %, рупии, бомбы, стрелы, ключи, имя и боезапас выбранного предмета. Компоненты Add UI берут их в размер, позицию, прозрачность и текст, в том числе выражением `@{переменная} * 36` (docs/UI.md). У `Show Stat In Variable` новые значения: здоровье, целые сердца, половинка, магия в %, имя выбранного предмета, «предмет выбран» и «предмет есть» (1/0) для любого предмета.
- `Zelda: HUD Style` → *Toolkit HUD parts*: какие части HUD рисует сам Toolkit (сердца, счётчики, рамка предмета, шкала магии); остальное можно собрать на Add UI.
- **Сообщения Toolkit — настоящим диалогом PS Maker** (`Message Style` → *Show with* → *PS Maker Dialogue*, по умолчанию): таблички и «Вы получили…» показывает PS Maker со всеми настройками макета диалога (имя, портрет, звук печати, анимации). Синтаксис диалога в тексте экранируется. Режим *Toolkit box* (окно Toolkit, как в 0.17.0) остался.
- Демо: HUD собран на Add UI (ряды сердец из повторяющейся картинки шириной по переменным, значки и числа счётчиков); Toolkit рисует фон полосы, рамку предмета и шкалу магии; таблички и предметы — диалогом PS Maker; картинки HUD в ×4 для слоя UI.

### Исправлено
- **Шрифт в окне сообщений** (сообщил пользователь: неправильный шрифт при получении предмета из сундука). PS Maker загружает шрифт проекта, только когда впервые показывает свой текст. В тесте, запущенном с игровой карты, этого не было, и текст Toolkit падал на браузерный serif. Теперь Toolkit загружает шрифт сам — так же, как PS Maker: в экспорте по пути `game-assets/…`, в настольном редакторе через `psMakerDesktop.storage.getAssetUrl`. Запасной шрифт — без засечек.
- Клавиша, закрывшая диалог PS Maker, больше не открывает сразу сундук или табличку перед игроком.
- Перезапуск Toolkit после загрузки сохранения определяется тем же признаком, что у PS Maker (`MapStartup.needsStart`).

## [0.17.0] — 2026-10-28

Интерфейс (просил пользователь: HUD из своих ассетов, главное меню, настройки, диалоговое окно, всё в демо). План — docs/UI_PLAN.md, описание — docs/UI.md.

### Добавлено
- **`Zelda: HUD Style`** — HUD Toolkit из картинок библиотеки *Images* PS Maker:
  - сердца (полное, половина, пустое) и надпись LIFE;
  - значки рупий, бомб, стрел, ключей и лента цифр 0–9;
  - рамка предмета, рамка и заливка шкалы магии;
  - фон полосы (9-slice);
  - шрифт проекта, цвет текста, масштаб.

  Раскладка учитывает размеры картинок; пустое поле — встроенная картинка.
- **`Zelda: Message Style`** — сообщения Toolkit (таблички, полученные предметы, подсказки, заметки — на выбор) в окне, нарисованном по макету диалога проекта: размер, отступы, фон цветом или картинкой 9-slice, шрифт, цвет, скорость печати. Текст печатается по буквам; клавиша действия показывает остаток, затем закрывает окно. Сообщения идут очередью, игра на это время ждёт. У `Show Message` появилась галочка *In a dialogue box*.
- **Прогресс Toolkit в сохранениях PS Maker:** `Start Toolkit` → *Progress variable* (текстовая переменная). Когда PS Maker загружает сохранение, Toolkit восстанавливает прогресс из переменной; когда переменная очищается (новая игра), начинает сначала.
- **Перезапуск после загрузки:** PS Maker не выполняет «Map start» карты, восстановленной из сохранения, поэтому Toolkit сам выполняет её действия `Zelda:`, которые строят карту (ENGINE_AUDIT, раздел 17).
- **Демо:**
  - титульная карта с главным меню на штатном Add UI: New game, Continue (меню загрузки), Settings (меню опций), Exit;
  - свои пиксельные картинки интерфейса в *Images* (`scripts/ui-assets.mjs`): рамка окна, кнопка, полоса HUD, сердца, значки, цифры, рамка предмета, шкала магии;
  - на них — макет диалога (по умолчанию), стиль кнопок, меню опций, загрузки и выбора;
  - HUD Style и Message Style на обеих картах;
  - житель у старта говорит штатным Dialogue;
  - табличка открывается в окне Toolkit;
  - переменная прогресса.

### Исправлено
- Звуки Toolkit не следовали ползунку *Sound Volume* меню опций PS Maker; теперь следуют, как звуки самого PS Maker.
- Клавиша, нажатая в меню опций, срабатывала в игре после его закрытия; теперь такие нажатия отбрасываются.

### Изменено: формы без JSON
Все поля, где нужно было писать JSON, заменены обычными полями: галочками, числами, короткими списками через запятую. Выпадающих списков и кнопок API плагинов PS Maker (0.0.3) не даёт — выбор из вариантов сделан галочками и числами.

| Действие | Было | Стало |
|---|---|---|
| `Start Toolkit` | Preset (текст), Config JSON | Difficulty (1–3), Hearts, Sword damage, Show HUD, Magic bar, Shield on a button, HUD at the bottom, Autosave, Positions in tiles |
| `Configure` | Config JSON | заменено на `Zelda: Set Controls` — клавиши по полям (`X`, `Space`, `Shift`, `Tab`, `Up`…) |
| `Create Enemy`, `Enemy From NPC`, `Add Wave Enemy` | Overrides JSON, Animations `walk=…` | Health, Damage, Speed (0 = как в шаблоне), Walk/Attack/Hurt/Death animation, Sprite offset X/Y, Sprite scale |
| `Create Object` | Config JSON | Hidden, Stays on, Width, Height, Text, Reacts to, On use: set flag / open doors / reveal |
| `Create Door` | Lock (текст) | галочки Needs a small key, Needs the Big Key, Opened by switch; Width, Height |
| `Add Rule`, `Run Actions` | When/Then/Else JSON | When group defeated, When objects active, When flag set, When player has, When boss defeated → Open doors, Reveal, Set flag, Give item + count, Message, Spawn enemy + marker |
| `Create Switch Sequence`, `Create Wave Room` | On solved / On cleared / Advanced JSON | те же поля действий; у комнаты — Pause between waves (ms) |
| `Change Player Stats` | Stat, Mode (текст) | Health, Max health, Magic + галочка Set instead of add |
| `Define Item` | Item JSON | Item ID, Name, Icon, Uses, Cost, Damage, Damage type, Area attack, Stun, Heal |
| `Define Enemy` | Template JSON | Based on, Health, Damage, Speed, Sight range, Boss, Immune to, Sprite offset/scale |
| `Define Animation` | Frames JSON по направлениям | Frames (facing down), Frames facing up / left / right |
| `Set Player Sprites` | Weapon behind in (текст) | четыре галочки направлений; Swing center X/Y |

**Совместимость.** Действия, сохранённые старыми версиями, продолжают работать: старые JSON-поля применяются с предупреждением «re-open the action», а новые поля, которых у старого действия нет, ничего не сбрасывают. Полный словарь правил и все настройки остаются в JS API (`ZeldaMakerToolkit.addRule`, `runActions` — новые, `configure`, `registerEnemyTemplate`, `defineItem`).
