# Тестирование

## Что запускалось фактически

Окружение: Node.js 22.22, TypeScript 5.9.3, Phaser 3.90.0, headless Chromium 1194 (playwright-core 1.56.1), 2026-10-25.

| Проверка | Команда | Результат |
|---|---|---|
| Типы (исходники и тесты, strict) | `npm run typecheck` | без ошибок |
| Юнит-тесты (`node:test`, фейковый хост) | `npm test` | **190 / 190** |
| Сборка официальным CLI | `npm run build` | `dist/zelda-maker-toolkit.ps-maker.js`, 42 действия, импорт в Node без побочных эффектов |
| Интеграция: бандл в реальном Phaser в Chromium через эмулятор хоста | `npm run test:integration` | **20 / 20**, без ошибок в консоли |

Всё сразу: `npm run check`. Отчёт интеграции и скриншоты: `tests/integration/.artifacts/` (не коммитятся).

**Исходный код рантайма PS Maker 1.2.1 (экспорт игры, 2026-10-25)** объяснил все наблюдения ниже: PS Maker ждёт `ctx.endAction()` от каждого действия, а Toolkit его не вызывал — событие останавливалось после `Start Toolkit`. Исправлено в 0.6.0; эмулятор хоста в интеграционном тесте теперь тоже требует `endAction` (см. ENGINE_AUDIT, раздел 11).

**Подтверждено пользователем в редакторе PS Maker (2026-10-20):** плагин 0.2.0 загружается из `/plugins`, действие `Zelda: Create Enemy` открывается с формой параметров; `position` отображается полями X/Y, `npc` — выпадающим списком «Select NPC». **Playtest 0.4.0 (скриншот пользователя, 2026-10-24):** `Zelda: Start Toolkit` выполняется, HUD и панель диагностики работают, игрок найден на сцене карты. В журнале было два подряд `Start Toolkit` и ни одного `Create Enemy` — то есть действие создания врага PS Maker не выполнял. В 0.4.1 повторный старт больше не пересоздаёт сессию, а панель показывает строку `actions run:`.

**Playtest 0.4.1 (скриншот пользователя, 2026-10-25):** `actions run: Start Toolkit x3`, `Create Enemy` снова не выполнялся; между стартами сцена карты закрывалась (`Stopped … (scene shutdown)`), в окне оставалась копия плагина 0.4.0. Гипотеза: PS Maker не доходит до вызова плагина, если не может подготовить параметр действия (у `Start Toolkit` только текст и флажки, у `Create Enemy` были Position и NPC). В 0.4.2 NPC вынесен в отдельное действие, а ошибки страницы и `console.error` попадают в панель.

**Playtest 0.4.2 (скриншоты пользователя, 2026-10-25):** в редакторе действие `Create Enemy` всё ещё сохранено версией 0.4.1 с полем *Use NPC* = Slime; в игре `actions run: Start Toolkit x2`, `Create Enemy` не выполнялся, ошибок в `problems:` нет. То есть PS Maker пропускает действие молча, не вызывая плагин. Проверка гипотезы про поле NPC требует пересоздать действие (в 0.5.0 у `Create Enemy` только текст, числа и Position).

**Не запускалось (мной):** сам редактор PS Maker и экспорт игры из него — их нет в среде разработки, сайт документации был недоступен. Эмулятор хоста воспроизводит только задокументированный контракт (`game`, `scene`, `player`), а не внутреннее устройство PS Maker.

## Ручные сценарии в PS Maker

Выполнить после установки `dist/zelda-maker-toolkit.ps-maker.js` в `/plugins`. Результат каждого шага сверить с ожидаемым; при расхождении приложить вывод консоли браузера (`[ZeldaMakerToolkit]`).

| ID | Сценарий | Ожидаемо |
|---|---|---|
| M-01 | Открыть проект, добавить событие: в списке есть действия `Zelda: …` | 42 действия; у *Position* — кнопка выбора на карте, у шаблона, типа объекта, замка, сложности — выпадающие списки. Если вместо них пустое или текстовое поле — сообщить версию PS Maker (значит, редактор рисует эти типы иначе для плагинов) |
| M-02 | On-load: `Zelda: Start Toolkit` (Map ID `test`), запустить playtest | В консоли нет ошибок; в левом верхнем углу HUD с сердцами |
| M-03 | `Zelda: Create Enemy` с Position | Слизень появляется в выбранной точке. Если смещён в ~16 раз — Position в тайлах: галочка *Positions in tiles* у `Start Toolkit` |
| M-04 | Подойти к врагу, нажать X | Меч виден в направлении взгляда, у врага −2 HP (F9: красный хитбокс), враг отлетает; во время удара игрок не двигается |
| M-05 | Дать врагу коснуться игрока | −1 HP, игрок отлетает и мигает ~1 с, повторного урона нет |
| M-06 | Стены карты | Враги и снаряды не проходят сквозь коллизии карты. Если проходят — в консоли предупреждение `No Arcade static bodies…`: коллизии PS Maker устроены иначе |
| M-23 | Start Toolkit + Create Enemy + Show Message в событиях начала карты, F10 | Враг на месте, сообщение показано; в `actions run:` — все три действия (PS Maker дошёл до конца события) |
| M-22 | `Create Enemy` с выбранным в списке *Look* персонажем Slime, F10 | Строка `PS Maker data:` показывает, где найдены данные проекта; слизень ходит анимациями Slime Run/Idle. Если «not reachable» — прислать скриншот панели и (по возможности) экспорт игры |
| M-21 | Открыть формы `Start Toolkit`, `Create Object`, `Add Rule` (0.5.0) | Нет полей с JSON; галочки и числа отображаются как флажки и числовые поля |
| M-07 | `Zelda: Enemy From NPC` с выбранным NPC | NPC становится врагом. Если нет — предупреждение `NPC "…" was not found`; сообщить, как выглядит значение параметра |
| M-08 | Сундук + дверь + ключ, смена карты туда-обратно | Сундук остаётся открытым, дверь — открытой |
| M-09 | Удалить плагин из `/plugins`, запустить проект без действий `Zelda:` | Проект работает как раньше. (С действиями `Zelda:` редактор, вероятно, покажет отсутствующий плагин) |
| M-10 | Открыть диалог PS Maker во время боя | Враги и снаряды замирают, пока диалог на экране, и продолжают после |
| M-11 | Экспорт Web/Itch.io | Игра работает, сохранения Toolkit в `localStorage` |
| M-12 | Клавиша Z рядом с NPC и сундуком | Проверить, что взаимодействие PS Maker и открытие сундука не конфликтуют; при конфликте сменить `controls.action` |
| M-15 | Playtest, F9, клик по карте | Появляется перекрестие и «X: … Y: … copied»; вставка в поле Position ставит объект в эту точку |
| M-16 | `Zelda: Start Toolkit` с *Show diagnostics* = true (или F10), затем `Zelda: Create Enemy` | В строке `actions run:` есть `Create Enemy`; в журнале — `Create Enemy {...}` с тем, что передал PS Maker, и `Enemy "..." spawned at X, Y`; враг в списке рядом с игроком с координатами. Если `Create Enemy` в `actions run:` нет — PS Maker это действие не запускал (оно в другом событии, после ожидания или условия). Если `Start Toolkit x2` — смотреть строку `Restarting: …` / `Already running …` |
| M-17 | Mana Seed: Define Sprite Sheet → Preview Sprite Sheet → Define Animation → Set Player Sprites | Лист показывается с номерами кадров; при ударе спрайт PS Maker скрывается и проигрываются кадры тела и оружия; после удара спрайт возвращается |
| M-18 | `Zelda: Set Sound` (Moment `swordSwing`, Sound — аудио-ассет), удар мечом | Звучит при каждом взмахе. Если нет — в диагностике строка `Set Sound {...}` покажет, что передал параметр `audio`; впишите ключ или путь в *Sound key or URL* |
| M-19 | Spawned NPC стоит между врагом и игроком | Враг упирается в NPC, а не проходит сквозь него |
| M-20 | On-load: `Start Toolkit` → `Show Message` (текст «1») → `Create Enemy` → `Show Message` (текст «2») | Видны оба сообщения и враг. Если видно только «1» — PS Maker остановил список на `Create Enemy`: в разделе `problems:` панели должна быть строка `console.error: …` / `Page error: …` с причиной. Если не видно и «1» — PS Maker не продолжает список после действия плагина |
| M-13 | Мобильное устройство | Тач-кнопка PS Maker не вызывает меч (ограничение API); сообщить, если нужна поддержка |

## Как писать новые тесты

- Логика: `tests/helpers/fakeHost.ts` → `createRig(config)` даёт `Toolkit`, `FakeHost` (игрок-бокс, стены, ввод) и `Session`; `rig.host.walk(dx, dy)` имитирует движение PS Maker, `rig.host.input.tap("sword")` — нажатие, `rig.run(ms)` — время.
- Phaser-адаптер: `tests/helpers/fakePhaser.ts` (эмиттеры со счётчиками) или интеграционный тест.
