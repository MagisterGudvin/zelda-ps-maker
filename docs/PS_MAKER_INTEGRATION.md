# Связка с PS Maker 1.x

Как сочетать Toolkit со штатными возможностями PS Maker 1.0–1.2 (титульный экран, сохранения, UI, диалоги, NPC, звук). Связь строится на событиях PS Maker, которые вызывают действия Toolkit, и на переменных проекта.

## Титульный экран и сохранения

Главное меню, сохранение и загрузка — штатные средства PS Maker (Add UI на титульной карте, меню опций и меню загрузки, см. [UI.md](UI.md)). Прогресс Toolkit (здоровье, предметы, сундуки, двери, подземелья) PS Maker сохраняет сам, если выбрать текстовую переменную в `Zelda: Start Toolkit` → *Progress variable*: Toolkit держит в ней свой прогресс, восстанавливает его, когда PS Maker загружает сохранение, и начинает сначала, когда переменная пуста (новая игра).

## Карты

- В «Map start» (When map first starts) **каждой** карты первым действием — `Zelda: Start Toolkit`, за ним враги, объекты, сундуки, правила. Объекты карты запоминаются по id карты в PS Maker и по месту объекта на карте.
- Переход между картами (штатное «Change map», например на триггере касания) ничего дополнительно не требует. PS Maker не запускает «Map start» повторно, когда вы возвращаетесь на карту: он «будит» её из сохранённого состояния. Toolkit сам выполняет снова действия, построившие эту карту (Start Toolkit, враги, объекты, сундуки, двери, правила, комнаты, настройки), а открытые сундуки, разбитые стены и взятые ключи остаются такими. Эффекты — `Give Item`, `Show Message` и т.п. — не повторяются.
- Если положить `Zelda: Start Toolkit` и остальное в «Map enter» (при каждом входе), это тоже работает: такой Start Toolkit заменяет автоматически восстановленную карту.
- Узкие проходы: PS Maker сам уводит игрока в обход угла, только если тот чуть сбоку от препятствия, поэтому двери и проходы удобнее делать в два тайла (у `Create Door` есть *Width*/*Height*).
- Твёрдые объекты Toolkit (блоки, сундуки, закрытые двери, горшки, кусты, камни) с 0.14.0 — статические тела физики PS Maker: игрок останавливается о них так же, как о стены карты, и обходит их края так же.

## NPC

- `Zelda: Enemy From NPC` берёт NPC, который **уже стоит на карте**: штатное действие появления NPC (Spawned NPC) должно идти раньше. Враг использует спрайт и анимации этого NPC.
- С PS Maker 1.1 у NPC есть коллизии. Toolkit тоже считает их препятствиями (`world.npcsBlock`): враги и снаряды не проходят сквозь NPC.

## Переменные проекта

Toolkit читает и пишет переменные проекта PS Maker (`game.variables`), поэтому события PS Maker могут ветвиться по состоянию игры:
- *Turn on variable* в правилах и *On use: turn on variable* у объектов — включают переменную (`true` или 1);
- *When variable is on* — условие Toolkit по переменной (её может менять и штатное действие PS Maker «Change variable»);
- `Zelda: Show Stat In Variable` — переменная всегда равна значению Toolkit: рупии, бомбы, стрелы, ключи текущего подземелья, сердца, максимум сердец, магия, враги на карте. Подходит для условий (магазин, дверь «нужно 3 ключа») и для UI-компонентов PS Maker.

Флаги Toolkit (`Set Flag`) заменены переменными проекта: действие удалено, используйте штатное «Set variable / Change variable».

## Диалоги и сцены

Пока на экране диалог PS Maker (`GameMap.playingDialogue`), бой стоит на паузе сам: враги и снаряды замирают, удары не проходят (с 0.6.0; отключается `combat.pauseDuringDialogue: false`). Для катсцен без диалога по-прежнему есть `Zelda: Pause Combat` (true / false).

## Звук

С PS Maker 1.1 звуковые ассеты стали полноценными. `Zelda: Set Sound` назначает звук моменту боя: `swordSwing`, `spinAttack`, `enemyHurt`, `enemyDefeated`, `playerHurt`, `playerDie`, `shieldBlock`, `bombExplode`, `objectBreak`, `pickup`, `itemGet`, `chestOpen`, `doorUnlock`, `puzzleSolved`. Если выбор звука в форме не сработал, впишите ключ или путь к файлу в *Sound key or URL*. Общая громкость и отключение: `{"audio":{"volume":0.7}}`, `{"audio":{"enabled":false}}`.

## Интерфейс и боевая система PS Maker

- Боевая система PS Maker 1.0 — пошаговая, собирается из UI-кнопок и событий. Бой Toolkit идёт в реальном времени прямо на карте. Их можно использовать в одной игре, но для разных сцен.
- HUD Toolkit рисуется поверх UI PS Maker; классический HUD не заходит в правый верхний угол (шестерёнка настроек), свой собирается в дизайнере `Zelda: UI Layout`. Если вы строите интерфейс на UI-компонентах PS Maker, удалите в дизайнере все элементы HUD (роль *HUD* без элементов — пустой HUD; экраны, уведомления и диалоги Toolkit продолжают работать), а значения Toolkit передайте в переменные действием `Zelda: Show Stat In Variable`. Галочки *Show HUD* у `Zelda: Start Toolkit` с 0.32.1 нет.

## Проверка

Если что-то не появилось или ведёт себя странно — `Zelda: Debug` (Diagnostics) или F10: на экране видно, какие параметры передал PS Maker, где созданы враги и объекты, какие были предупреждения.

## Порядок действий в событии

PS Maker выполняет действия события по очереди и ждёт, пока каждое сообщит о завершении (`ctx.endAction()`). Все действия Toolkit завершаются сразу после своей работы, так что их можно ставить в любом порядке вперемешку со встроенными. До 0.6.0 действия Toolkit этого не делали, и событие останавливалось на первом из них — поэтому `Create Enemy` после `Start Toolkit` не выполнялся (подробности — ENGINE_AUDIT, раздел 11).
